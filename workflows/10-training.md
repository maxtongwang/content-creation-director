# 10 · 编导训练

**何时用**：用户想自己学会，不只是要一份成品。
或者：同一类问题反复出现，说明是能力问题不是单条内容问题。

**目标：让用户下次自己能做，而不是下次再来问。**

---

## 训练什么

对应四项底层能力：

| 能力 | 表现为 | 回流到 |
|---|---|---|
| **选题** | 热点判断、需求感知、共情力 | `3-topic` |
| **钩子** | 标题、封面、第一句 | `4-hook` |
| **结构** | 脚本骨架、节奏、分镜 | `5-script` |
| **定位** | 商业逻辑、禁区、人设一致性 | `1-account` `2-ip` |

**识别薄弱项**：看用户在哪个环节最常返工。返工最多的就是最弱的。

---

## 训练方法：真实任务 + 前后对照

**不做练习题，用他手上真实的东西。**

### 第一步 · 让他先做

```
「这条选题你自己先写三个标题，写完我们对照。」
```

必须**他先做**。看了答案再学，学不会。

### 第二步 · 前后对照

并排放，不评价好坏，只标出差异和原因：

```markdown
| 你写的 | 改后 | 差在哪 |
|---|---|---|
| 分享一些看房的心得 | 今天跑了六个地方，午饭在车里解决的 | 抽象 → 具体时刻 |
| 房产投资的三个要点 | 看了 100 套之后，我发现最值得买的是这一种 | 说明 → 结果悬念 |
```

**「差在哪」那一列是训练的全部价值。**只给改后版本，他学不到规则。

### 第三步 · 验收标准

给一条**他自己能用的判断标准**，不是感觉：

```
标题验收：
- [ ] 有没有一个具体的东西？（数字、地点、时刻、动作）
- [ ] 去掉形容词还剩什么？剩不下就是空的
- [ ] 念一遍，像不像人话
```

下次他自己能对照这个表检查。

---

## 训练的三个层次

按用户当前水平选：

| 层次 | 做法 | 适合 |
|---|---|---|
| **模仿** | 给模板，他填空 | 完全新手 |
| **对照** | 他先做，再对比 | 有基础，会但不稳 |
| **反证** | 他做，我只挑毛病不给答案 | 已经会了，要提高上限 |

**不要跳级。**新手直接进反证会崩，老手停在模仿会烦。

---

## 一条重要提醒

**不要把训练变成打分。**

目标是让他建立自己的判断，不是让他依赖你的判断。
所以每次训练结束都要给「验收标准」——**那是他带走的东西**，比改好的稿子重要。

如果每次都只给改后版本，三个月后他还是要来问。

---

## 循环

```
训练 → 发现薄弱能力 → 回对应环节重做一遍 → 下次任务观察是否改善
```

改善了就升一个层次（模仿 → 对照 → 反证）。
没改善就换个角度切入，同一套讲法讲三遍还不通，多半是讲法的问题。
