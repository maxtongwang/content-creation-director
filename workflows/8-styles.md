# 8 · 风格档案

> ⚠️ **本文里的倍率都是 📊 = 样本，不是常数。**它们证明「那个测法能测出东西」，**不代表你的账号会得到同一个数** ——看 🔬 测法，用自己的数据重跑。见 `SKILL.md` 原则三十四。

**产出**：`profile.yaml` 的 `styles` 段
**何时用**：用户有不止一种内容形态（多数博主都有）

---

## 零、先问产品类型 —— 它比风格偏好优先

| 产品 | 形态 | 为什么 |
|---|---|---|
| **服务型**（咨询 / 经纪 / 教练 / 设计） | **vlog** | 卖的是「跟这个人合作是什么感觉」，只有过程能展示它 |
| **资料型**（课程 / 模板 / 报告） | **口播干货 / 图文** | 卖的是信息，信息密度越高越好 |

**混合型**（主服务 + 少量资料）按 share 分配形态，不要一种形态打天下：

```
服务型主线（多数）   vlog        → 信任层
资料型注脚（少数）   口播 / 图文  → 流量层 + 收藏
```

⚠️ **不要用曝光 ROI 评服务型的 vlog** —— 见 `references/method-account.md`「产品类型直接决定形态」。

⚠️ **资料型 ≠ 可以讲授。**形态定了「口播干货 / 图文」，**调性仍然是分享 / 展示 / 沟通** ——
必须用大白话、必须有例子。见 `5-script`「调性是三个动词」。
一个账号连发 24 条术语词典换来 0 条咨询，死在这里，不是死在形态上。


## 为什么必须显式定义

一个博主常同时有：一镜到底口播、精剪 vlog、b-roll 配音、图文。

这四种的**剪辑参数完全不同**——切镜密度、BGM、字幕、口播处理、时长弹性全不一样。
如果只有一套 profile，AI 剪辑会用同一套参数处理所有素材，结果就是「哪种都不像」。

**风格不是标签，是一组剪辑参数。**

---

## 一、识别用户已有的风格

对老手：翻他已发的内容，按**观感**分组，不按主题分组。

```
❌ 按主题分：房产 / 网球 / 美食        → 这是支柱，不是风格
✅ 按观感分：一镜到底 / 快剪 / 慢氛围   → 这才是风格
```

判断依据：
- 平均镜头长度差异大吗？
- 有没有 BGM？音乐类型一致吗？
- 口播是主干还是配角？
- 字幕样式一样吗？

对新手：先定 **1–2 种**，跑顺了再加。多了会稀释识别度。

---

## 二、固定元素 ★ 长期记忆

**用户说过一次的固定元素，永远不要再问第二遍。**

「我的 vlog 都有个固定片头」「我每期都会说那句口头禅」「我的固定环节是今日三件事」——
这些一旦说出口，就写进 `profile.styles.<风格>.fixed_elements`，
之后 `5-script` 和 `6-edit` **每次自动带上**。

```yaml
fixed_elements:
  开场: <固定片头 / 固定第一句 / 固定动作>
  口头禅: [<每期都会说的话>]
  固定环节: [<每期必有的段落>]
  固定道具: [<反复出现的物件>]
  bgm: <固定曲目或曲库>
  转场: <固定转场方式>
  字幕样式: <字体 / 位置 / 颜色>
  片尾: <固定结尾句 / 固定动作>
  禁用: [<这个风格里绝对不做的>]
```

### 为什么这是最值钱的一段

| 没有它 | 有了它 |
|---|---|
| 每次写脚本都要重问一遍片头怎么开 | 直接套用 |
| 每条视频的观感都不太一样 | 有识别度 |
| 用户觉得「这 AI 记不住事」 | 越用越顺手 |

**固定元素就是账号的识别度来源。**观众记住一个号，
往往先记住的是那句口头禅、那个片头、那个固定环节，而不是某一条内容。

### 怎么获取

| 场景 | 做法 |
|---|---|
| 用户主动说 | 立刻记下来，写进 profile |
| 用户没说 | 有 MCP 就扫（`1d-scan` 拉字幕能看出口头禅） |
| 都没有 | 做完第一条内容后问一次：「这些以后每期都保留吗」 |

**不要一上来就问一长串。**边做边攒，做完一条问一句。

## 三、每种风格必须定义的字段

```yaml
styles:
  <风格名>:
    when: <什么内容用这个风格>
    script_structure: 讲故事 | 晒过程 | 教知识 | 聊观点 | 尬段子 | 说产品
    form: 出镜 | b_roll_vo | 图文 | 情景剧

    edit:                          # ★ 核心：剪辑参数
      pace: 慢 | 中 | 快
      avg_shot_sec: [<下限>, <上限>]
      cut_density: <每分钟切镜数>
      transition: 硬切 | 匹配剪 | 叠化
      bgm: none | 低 | 中 | 高
      subtitle: 无 | 基础 | 花字
      vo_handling: 全保留 | 删长静默 | 紧凑     # 见下方冲突说明
      speed_ramp: false | true                # 慢节奏段是否加速
      color: 原生 | 统一调色

    identity:
      self_presence_required: true | false
      max_gap_seconds: <n>
      min_ratio: <0-1>

    reference: <一条自己的成片作为基准>        # 最重要的一行
```

**`reference` 那行最重要**——一条已存在的、你认可的成片，
胜过十行参数描述。AI 剪辑对齐的是它，不是形容词。

---

## 四、vo_handling 的选边

这一项有真实分歧，按风格选，不要全局统一：

| 取值 | 做法 | 适合 |
|---|---|---|
| 全保留 | 保留口误、停顿、被打断，只剪 >3s 静默 | 生活类、人设类——**人味儿即可信度** |
| 删长静默 | 剪气口但保留语气 | 中间态 |
| 紧凑 | 删气口和废话，慢段加速 | 干货教学类——**播音感即专业感** |

同一个博主的不同风格可以取不同值。这不矛盾。

---

## 五、自动识别（给 AI 剪辑用）

`6-edit` 阶段拿到素材后，先判断属于哪种风格，再套对应参数。

判断依据（按优先级）：

```
1. topic-card 里已声明 style      → 直接用
2. script.yaml 的 structure + form → 反查 styles 表
3. 素材特征推断（见下）            → 匹配最接近的
4. 都不确定                        → 问用户，不要猜
```

### 素材特征推断表

| 特征 | 指向 |
|---|---|
| 口播占比 >70%、场景单一 | 一镜到底口播 |
| 场景 ≥3 个、有移动镜头 | vlog / 日常 |
| 口播完整但画面零散、无同期声 | b-roll + 配音 |
| 静态图为主 | 图文 |
| 有明显对话、多人 | 情景剧 |

**第 4 条是硬规则**：识别不出就问，宁可多问一句，不要剪出四不像。

## 六、风格与支柱是两个维度

```
支柱 = 拍什么（房产 / 网球 / 财经）
风格 = 怎么呈现（口播 / vlog / b-roll）
```

**它们可以自由组合。**同一个支柱可以用不同风格拍，
同一种风格可以拍不同支柱。

在 `topic-card` 里两者都要声明：

```yaml
pillar: <支柱>
style: <风格名>
```

## 七、风格漂移检查

定期查：某种风格的实际成片，是否还符合它的参数定义？

漂移常见原因：
- 素材不够，被迫用别的风格的镜头补
- 剪辑时临时改了节奏
- 参数定得太理想，实际做不到

**处方**：要么改参数向现实靠拢，要么补拍。不要放任漂移——
风格漂移三个月，账号就没有识别度了。

## ★★★ 三组最容易混的「形式 vs 内容」

编导最贵的三次返工都来自同一类误读：**把形式层的东西当成内容层来解。**

### 一 · 载体 ≠ 题材

用户说「**X 是我最好的连载载体**」。

```
❌ 我读成   X = 拍 X 的内容        → 去研究「X 类内容怎么做」（实测那一档 0.62×，最差之一）
✅ 实际是   X = 每周 N 个录制窗口   → 内容照旧，只是挂在这个节奏上
```

**「载体」回答的是「什么时候拍」，不是「拍什么」。**

★ 判断方法：问用户「**这件事会出现在内容里，还是只是你做内容的时间点？**」
一句话就能分开，而我用了整整一轮搜索才发现问错了问题。

⚠️ 真实代价：因为这个误读，我跑了两轮全平台采集（1,300+ 条），
**得出的全部结论都答非所问。**

### 二 · 外壳 ≠ 结构

用户提「**用日记形式**」。

| | 长什么样 | 结果 |
| --- | --- | --- |
| ❌ **日记当结构** | 「今天练完，说说我最近的一些想法」 | **无对象 = 流水账**（撞[对象闸门](#)） |
| ✅ **日记当外壳** | 「今天练完，忽然想起某年那件事」 | 内容是原来那条，只是用今天挂进来 |

**判据一句话：拿掉开场那两句，这条还完整吗？**
完整 → 是外壳。不完整 → 是结构，退回。

⚠️ 数据答不了这个问题（三个切法三个方向、n 都不干净）——
**所以别拿流量当选它的理由。外壳的价值在成本：零准备、事件锚天然有、状态真实、一致性。**

### 三 · ★★ 内容和时机可以解耦 —— 空格子不一定要用新内容填

我量出一个空格：**`低成本 × 持续供给` = 0 条**（所有低成本内容都是存量，所有持续供给的都要出门），
然后**发明了一条内容线去填它 —— 当场被否。**

**真正的解法是解耦：**

```
内容是存量（来时路）  ×  触发是当下（今天做了什么）
    ↓
「今天练完，忽然想起某年那件事」= 存量内容 × 当下触发
```

**空格子不一定意味着缺内容，可能只是缺一个把存量挂到当下的封装。**
⚠️ 先问「能不能换个封装」，再考虑「要不要造新内容」。

## ★★ 能用物理约束表达的规则，不要用约定表达

同一条规则，两种写法：

| | 写法 | 会怎样 |
| --- | --- | --- |
| ❌ **位置约定** | 「固定镜头放片头，不要放进叙事」 | 要记、会忘、破了没人发现 |
| ✅ **物理判据** | 「固定镜头**不出现人**」 | **人一入镜，画面就带了当天的信息**（穿什么、状态、天气）—— 复用立刻露馅，**物理上就不会错** |

**两条管的是同一件事（可复用的素材不能撒谎），但第二条不需要任何人记住它。**

★ 通用做法：写下一条规则后问一句 ——
**「有没有一个物理事实能让违反它变得不可能？」**有就换成那个。

⚠️ 这条是用户提出来的，不是编导想到的。**用户更了解自己的物理约束** ——
同一轮里他连续三次给出比编导更好的方案（形式、锚的解耦、这条判据），
共同点都是**他知道现场实际长什么样**。

---

## ★★★ 「发明」的三级递进 —— 越往后代价越大

同一个项目里连续四次发明被否，**但它们不是同一种错，而是递进的**：

| 级 | 长什么样 | 代价 |
| --- | --- | --- |
| **一 · 发明一个形式** | 用户要「一个记号」，编导设计了五个（道具/口头禅/固定收尾），四个零出处 | 被否就没了，**无外部代价** |
| **二 · 为了填自己量出的空格而发明** | 编导量出一个数据空缺，**造一条内容线去填** | 🔴 **自欺** —— 因为有数据背书，看起来像有依据 |
| **三 · 越伦理边界** | 提议把用户的私人社交场合当素材来源 | 🔴🔴 **代价落在用户的关系和信用上，且不可逆** |

**原则十四写了「不要现场发明」，但它只挡得住第一级。**

| 加两道 | |
| --- | --- |
| **挡第二级** | **量出空格 ≠ 授权发明。**空格只说明该去问，不说明该去造 |
| **挡第三级** | **任何涉及第三方的内容源，先问「这个人知道并同意成为素材吗」。**不知道 = 不用，不管数据多好看 |

### ★ 找不到答案时，正确做法是说「这个需求可能不成立」

把用户一周的每一项逐个过完、逐个被否之后 —— **那不是搜索失败，那是一个结论。**

一个真实案例：用户要「可持续更新的连载」，把他一周的六件事全过完，**全部否掉**。
正确的回应不是造第五个方案，是：

```
你的一周里没有一件「每周必然发生 + 能出内容 + 你愿意讲」的事
→ 这个需求现在不成立，而且不成立不是坏事：
   ① 支撑它的数据本来就薄（n=25，且混着「有系列的账号更认真」这个变量）
   ② 你不缺内容 —— 存量够跑一个季度
   ③ 一个季度里那些正在进行的事会自己出结果，到时候是真实完成的事，不是现在编的格式
```

**说「不成立」需要拿出三条理由，否则那只是放弃。**
