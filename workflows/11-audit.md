# 11 · 全量审计

**何时用**：用户要求「按流程重新审视已做的东西」，或怀疑此前的产出没走流程。

**产出**：审计报告 + 修正清单 + 回流指令

---

## 审计对象

逐一检查每个已产出的文件，问三个问题：

1. **它是走哪个环节产出的？** 说不出来 → 大概率没走流程
2. **那个环节的必做项做了吗？** 对照该 workflow 的清单逐条查
3. **有没有基于推断而非事实的内容？** 尤其是用户的经历、数据、身份

---

## 逐环节检查清单

| 环节          | 必须存在的证据                                                            |
| ------------- | ------------------------------------------------------------------------- |
| `1-account`   | `profile` 有 business / targets / forbidden_topics，且 forbidden **非空** |
| `1b-discover` | 支柱是从「事实挖掘」来的，不是从题材猜的                                  |
| `1c-backfill` | 有断层报告（说的 / 做的 / 观众认知 三者对比）                             |
| `1d-scan`     | 每个字段标了 `scanned` / `inferred`，推断项给用户确认过                   |
| `2-ip`        | `ip_analysis` 已填，且过了颠覆 / 可持续 / 缺点三道检查                    |
| `3-topic`     | **选题卡最小字段集全齐** —— 闸门结果 · 爆款元素 · **爆款类型** · 四条件 · **作品目的** · **脚本结构** · **呈现形式** · 四来源标注 · 今天能做/需补拍 |
| **方法论对照** | ★ **`method-account` 与 `method-viral` 逐条过**，不是只对照本表 —— 见下 |
| `4-hook`      | 标题 **≥10 个**，覆盖全部句式；封面有取景描述，不是「拍好看点」           |
| `5-script`    | 每个镜头有 `cut_reason`                                                   |
| `6b-autoedit` | 配音模式合规；粗剪后**停下来等过**，没有自行渲染                          |
| `7-review`    | 结论写回了 `learned`，不是只在对话里说过                                  |
| `8-styles`    | 每种风格有 `reference`（一条真实成片）                                    |
| `9-deliver`   | 三条硬标准逐条过                                                          |

---

## ★ 先对照方法论，再对照本表

**本表是摘要，不是替代品。**只按本表查，会漏掉方法论里有、本表没列的判据。

开工前把这两份打开，逐条对：

| 文件 | 对什么 |
|---|---|
| `references/method-account.md` | IP 五要素（**道具最常被跳过**）· 账户四件套 · 八标签 · **脚本结构六种** · **呈现形式四选** · **漏斗四形态** · 转化=闸门 |
| `references/method-viral.md` | 爆款四条件 · **三类型** · **作品目的五型** · **涨粉两条路** · 未完结叙事 · 「只要我有」五问 / 「只要你要」六选题 · 分镜 |

### 实测：这一步不做会怎样

一次真实审计里，按本表查全部合格；**打开方法论逐条对，缺三项**
（作品目的五型 · 脚本结构六种 · 爆款三类型），
另有两项从没落实过（IP 五要素的**道具** · 漏斗形状**从未画过**）。

**原因**：`SKILL.md` 曾把这两份标为「需要时再读，不要预读」，
而本表又没把它们的必做项列全 —— **两头都以为对方覆盖了**。

## 常见失效模式

| 模式                   | 症状                                                   |
| ---------------------- | ------------------------------------------------------ |
| **凭记忆代替执行**     | 参与写过 skill，于是「知道里面写了什么」，不再打开文件 |
| **闸门形同虚设**       | 自己标了 ⚠️ 却仍放行                                   |
| **来源不全**           | 四个选题来源只用了一两个                               |
| **推断当事实**         | 用户的经历靠公开数据推断，未核对 `ip_analysis`         |
| **给建议不给成品**     | 产出是「建议你考虑」而不是可直接用的东西               |
| **数量缩水**           | 该给 8 个选题给了 3 个，该给 10 个标题给了 3 个        |
| **价值观层被数据改写** | 因为「这样数据更好」动了 `tone` / `forbidden_topics`   |
| **操作层被统计量改写** | 用调研中位数 / 相关系数覆盖了 profile 里既有的定位规则。定位是闸门、数据是放大——**数据没有改写定位的权力**。这条不只适用于价值观层，操作层同样 |
| **给碎片单独立块** | 把用户的一个爱好 / 身份碎片单独立成板块，结果账号变成「XX 号」。判据：**给它一个单独的位置，账号会不会变成 XX 号？** 会 → 拆进画面 / 身份 / 选题三个通道；不会 → 才考虑立块 |
| **凭空设计形式与命名** | 形式、系列名、结构由模型想象产出，没有对标真实样本。用户连续否决时，往往不是名字不好，**是这个格子本身不该存在** |
| **清单合格但方法论缺项** | 只对照 `11-audit` 的摘要表，没打开 `method-account` / `method-viral` 逐条过。**症状：审计结论是「合格」，但作品目的、脚本结构、爆款类型三项从来没标过** |
| **只要你要六选题硬凑** | 那六个（年少有为 / 大器晚成 / 造梦狂人 / 草根逆袭 / 逆风翻盘 / 苟富贵勿相忘）是给**创始人 IP** 的。用户不是创业者时，**多数不适用**。硬凑就是编造经历，直接撞 `9-deliver` 第二条。**能对上一两个就写一两个** |
| **相关当因果** | 全样本相关系数没做同号内 / 同期内分层就当结论。最常见的混杂是**发布期**与**账号涨粉阶段** |

第一条最隐蔽：**参与写过标准的人，最容易以为自己在执行标准。**
记忆里的版本停在写它的那一刻，之后的修订全都不在。

## 怎么查「有没有真读」

不看结论，看**证据**：

| 有                                   | 没有                     |
| ------------------------------------ | ------------------------ |
| 声明行里列了文件，且有对应 view 记录 | 只写了环节名             |
| 引用了该 workflow 里的具体判据       | 说法泛泛，换个环节也成立 |
| 数量、字段名与模板一致               | 数量不对，字段名对不上   |

**说不出「哪一条规则要求这么做」，就是没读。**

### 再加一条：说得出规则，但说不出它在哪份文件里

能背出「爆款八标签」不等于读过 `method-account` ——
**记忆里的版本停在上次读它的时刻，而方法论是会更新的。**
判断标准是**这一轮有没有 view 记录**，不是「我知道那里面写了什么」。

### 用户连续否决时，先怀疑前提

> **用户连续两次以上否决同一类产出时，停止改进方案，
> 去查这一类产出在平台上的真实采用率与数据。**

**大概率是前提错了，不是执行错了。**
第三次改进一个本不该存在的东西，比前两次更浪费。

## 输出格式

```
## 审计结果

| 文件 | 应走环节 | 实际 | 判定 |
|---|---|---|---|
| xxx | 3-topic | 未跑闸门 | ❌ 需重做 |
| yyy | 4-hook  | 只给 3 个标题 | 🟡 需补 |
| zzz | 2-ip    | 齐全 | ✅ |

## 修正清单
按优先级排序，每条标明回哪个环节

## 记入 learned
失效模式写进 learned.fails，同类不再犯
```

---

## 两条原则

**审计不是自我批评，是把「哪里没按标准做」变成可执行的修正清单。**
判定要具体到「缺哪一项」，不要停在「做得不够好」。

**审计自己也要走流程。**本环节的产出同样过 `9-deliver`——
一份没有具体修正指令的审计报告，本身就是「给建议不给成品」。
