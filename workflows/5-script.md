# 5 · 脚本与分镜

**输入**：`topic-card.yaml`（含 hook）
**产出**：`script.yaml` —— 这是全流程信息密度最高的文件，直接决定剪辑质量
**方法论**：`references/method-viral.md` 分镜章、`references/method-account.md` 内容体系章

---

## ★ 先说优先级：画面解释不了数据差异

**画面能解释的差异，远小于选题能解释的差异。**

实测：三个高数据账号约 230 条评论做关键词扫描
（画面 / 收音 / 拍摄 / 器材 / 镜头 / 背景 / 麦 / 字幕 / 剪辑 / 抖 / 风声 / 音质 /
打光 / 机位 / 三脚 / 支架 / 念稿 / 提词）——
**命中 6 条，全部正面或中性，零条负面。**

> **观众不讨论画面，观众讨论内容。**

| 对照 | 结果 |
|---|---|
| 同一个人、同一套器材、同一形态 | 6,359 赞 vs 223 赞，**差 28 倍**，差在选题 |
| 一个千万级从业者，同样的画面手法，选题换成「自己的产品」 | 赞中位掉到 **4** |

**所以：分镜方法论用来保证「能拍完、不返工」，不要指望它拉高数据。**
用户在纠结画面时，先把他拉回选题。

### 唯一值得投入的画面事项：解放双手

一个 56,214 粉账号的作者，被问「拍这个视频你换了多少角度」，原话回复：

> 「主要是两个机位：智能眼镜和运动相机。」

那是他 61 条里最高的一条。**不需要三脚架、不需要第二个人、不需要举手机。**

这是「场景不限」能成立的**物理前提**——手被占住，能拍的场景就只剩坐着说话。

⚠️ 心理预期要给到：那个账号 61 条**赞中位 239、最低 34**。
爆的那条是选题炸了。**形态保证你能持续拍，不保证数据。**

### 时长不设限

不要给时长开处方。实测跑赢的样本跨度 **20 秒到 194 秒**：

```
102s / 36K      169s / 6,359      91s / 4,956
194s / 10.5K    20s / 377赞96藏
```

中位数是**描述**，不是处方。

> 判据：**这条讲清了一件事吗？**
> 讲完了就停，没讲完就继续。**时长是结果，不是目标。**

写死一个时长窗口＝给自己上锁，见 `3-topic.md` 系列命名四关的推广。

## 一、选脚本结构（六选一为主）

```
讲故事 · 晒过程 · 教知识 · 聊观点 · 尬段子 · 说产品
```

**选一种为主，最多掺一种为辅。三种混一起就散了。**

| 结构 | 主线是 | 适合 |
|---|---|---|
| 讲故事 | 时间线 | 经历、案例、创始人 |
| 晒过程 | 步骤 | 工作日常、制作、跟进 |
| 教知识 | 逻辑 | 干货、词条、攻略 |
| 聊观点 | 论证 | 立场、行业判断 |
| 尬段子 | 包袱 | 轻松内容 |
| 说产品 | 卖点 | 转化 |

## 二、口播主干（不是逐字稿）

**先写骨架，不写逐字稿。**逐字稿会被念得不像人话，而且锁死时长。

### 四段骨架

| 段 | 作用 | 引导问题 |
|---|---|---|
| **HOOK** | 让人停下 | 此刻最反常/最具体的一件事是什么？ |
| **SETUP** | 交代处境 | 我在哪、要干嘛、为什么是今天 |
| **BODY** | 讲透 | 3–5 件事，每件一段，讲完一件再下一件 |
| **CLOSE** | 收 | 今天最真实的感受 或 一句判断 |

**BODY 的段数由内容决定，不由目标时长决定。**

### 口播质感

- 保留口误、停顿、被打断——那是可信度
- 短句，一句话一个意思
- 具体优于抽象

## 三、分镜（本阶段的核心产出）

**每一个口播语义段，配 1–3 个镜头。**

### 切镜三依据（切之前自查）

以下**任意一项发生变化**才切：

| 依据 | 说明 |
|---|---|
| 信息改变 | 前镜交代动作，后镜补充细节或场景 |
| 情绪改变 | 平静转紧张、开心转失落 |
| 视角改变 | 客观镜头切人物主观视线 |

**切镜无因等于零**——同款景别连接只是重复信息，不如不切。

### 理由前置公式

```
铺垫  →  切镜  →  兑现
```

前一镜埋理由（皱眉、眼神、台词），后一镜放出解释。
**拒绝到点机械切镜**——靠镜头内容做转场，不靠时长。

### 3W 默认模板（新手直接套）

```
Where 全景 → 交代环境
Who   中景 → 展示人物在做什么
What  特写 → 放大关键细节
```

### A-ROLL / B-ROLL 分层

```
A-ROLL：口播、对话、主线 —— 讲清「发生了什么」
B-ROLL：空镜、细节、动作 —— 丰富与转场
```

剪辑时**保留 A-ROLL 的声音，画面切到 B-ROLL**。

### 若本条是 b-roll + 配音（无完整出镜）

额外满足：
- 本人画面间隔 ≤90 秒
- HOOK 或 CLOSE 至少一处本人入画
- 本人入画时长占比 ≥15%
- **必须含一处只有本人能说的具体经验**（第一人称细节）

最后一条是关键。没有它，b-roll 内容三个月后就跟满大街的口播号一样。

## 四、镜头表字段

每个镜头必须写清（这是 `edit-plan` 的原料）：

```
shot_id      编号
role         HOOK / SETUP / BODY-n / CLOSE
type         A-ROLL / B-ROLL
size         远景 / 全景 / 中景 / 近景 / 特写
subject      self / 物 / 环境 / 他人
motion       固定 / 手持 / 运动
cut_reason   信息 / 情绪 / 视角      ← 没有理由就不该有这个镜头
audio        同期声 / 环境音 / 静音
vo_segment   对应哪一段口播
note         要拍到什么
```

## 五、拍摄清单（给用户带出门用）

从镜头表反向汇总：

```
地点清单     去哪几个地方
必拍镜头     不拍就补不回来的
备用镜头     有余力再拍
道具         profile 里定的那个道具带了吗
注意事项     隐私打码、授权、光线
```
