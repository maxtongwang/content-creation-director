# 4 · 标题 · 封面 · 开头

**输入**：`topic-card.yaml`
**产出**：`topic-card` 的 `hook` 段

三件事解决同一个问题：**让人停下来，并且点进去。**

---

## 一、标题

### 三种句式

| 句式 | 原理 | 例 |
|---|---|---|
| **身份反差** | 用身份与场景的错位制造好奇 | `[意外身份]做[意外的事]，看法不太一样` |
| **结果悬念** | 给出数量或过程，藏起结论 | `做了 N 次之后，我发现最有用的是这一种…` |
| **日常切片** | 白描一个具体时刻，不解释 | `今天跑了六个地方，午饭在车里解决的` |

### 硬约束

- 小红书 **≤20 字**（硬上限，超出被截）
- 不夸大、不用感叹号堆砌
- 不出现「咨询 / 联系 / 私信」
- 具体优于抽象：数字、地点、时刻 > 形容词

### 搜索型例外

若是搜索型内容（词条、攻略、教程）：

```
关键词必须在最前面
直白，不做悬念
唯一该带地名的内容类型
```

## 二、封面

**用场景，不用文字板。**

| 内容类型 | 封面取什么 |
|---|---|
| 人设 / 观点 | 能体现身份的场景 |
| 生活 / 兴趣 | 动态瞬间，不是摆拍 |
| 干货 / 攻略 | 结果画面或对比 |

### 文字层

- 放**安全区**（画面中上部），避开底部和两侧 UI
- **≤10 字**
- 大字、高对比，不玩花体
- 固定位置放系列角标

### 若走 Open Gate（原画幅直发）

竖屏平台上画面偏小，**上方留白带是关键资产**：
第一帧就放大字标题；下方留白保持空白（平台 UI 占用）。

## 三、开头（第一句 + 第一画面）

### 铁律

**不自报身份。**「大家好我是做 X 的」立刻掉完播。
身份靠简介承载（见 `2-ip.md`）。

**邀请绝不放开头。**片头一推销，完播率必掉。

### 第一句：六类句式库

卡住时从这里挑一句就开口。

**A. 具体时刻**（最安全，永远能用）
- 现在是[时间]，我在[地点]……
- 刚从___出来，路上想到一件事
- 今天第 N 个地方了，这是最后一站

**B. 反常**（最抓人）
- 这个我真没想到
- 本来今天休息的
- 说实话我今天挺意外的

**C. 直接抛问题**
- 有人问我___，我今天正好碰上了
- 你们猜这个多少钱

**D. 数字开场**
- 我算了一下，一共___
- 这个月第 N 次了

**E. 半句话（悬念）**
- 这个事儿……有点难讲
- 我先不说结论

**F. 场景白描**（适合 b-roll）
- 这条街我每周都要过好几次
- 你看这个位置

### 第一画面

要求：**有动作、不静止、不是人脸大头照**。

配合分镜的 3W 原则：开头常用**全景交代环境**或**特写抛出反常细节**，
不要用中景平铺直叙。

## 交付：多给，别只给一个

**用户来要标题，不是来给标题打分的。**
就算他贴了一个自己写的标题问「怎么样」——先给十个，再说他那个的问题。

| 给什么 | 至少 | 怎么给 |
|---|---|---|
| 标题 | **10 个** | 三种句式各 3 个以上，多平台时分平台各给一组 |
| 封面 | **3 个** | 取景描述 + 文字层，不是「拍得好看点」 |
| 第一句 | **5 句** | 覆盖不同句式，每句都能直接念出来 |

给完**排个序**，标出推荐哪个、为什么。**最终挑选权留给人。**

### 先读 learned

`profile.learned.works` 里已验证有效的句式**优先多给几个**；
`fails` 里证伪过的**不要再提**。见 `workflows/7-review.md`。

### 多平台

标题分平台各给一组——小红书 ≤20 字且关键词前置，
YouTube 和缩略图一起想。见 `references/platform-playbook.md`。
