# 4 · 标题 · 封面 · 开头

**输入**：`topic-card.yaml`
**产出**：`topic-card` 的 `hook` 段

三件事解决同一个问题：**让人停下来，并且点进去。**

---

## 一、标题

### 三种句式

| 句式 | 原理 | 例 |
|---|---|---|
| **身份反差** | 用身份与场景的错位制造好奇 | `[意外身份]做[意外的事]，看法不太一样` |
| **结果悬念** | 给出数量或过程，藏起结论 | `做了 N 次之后，我发现最有用的是这一种…` |
| **日常切片** | 白描一个具体时刻，不解释 | `今天跑了六个地方，午饭在车里解决的` |

### 硬约束

- 小红书 **≤20 字**（硬上限，超出被截）
- 不夸大、不用感叹号堆砌
- 不出现「咨询 / 联系 / 私信」
- 具体优于抽象：数字、地点、时刻 > 形容词

### 搜索型例外

若是搜索型内容（词条、攻略、教程）：

```
关键词必须在最前面
直白，不做悬念
唯一该带地名的内容类型
```

## 二、封面

**用场景，不用文字板。**

| 内容类型 | 封面取什么 |
|---|---|
| 人设 / 观点 | 能体现身份的场景 |
| 生活 / 兴趣 | 动态瞬间，不是摆拍 |
| 干货 / 攻略 | 结果画面或对比 |

### 文字层

- 放**安全区**（画面中上部），避开底部和两侧 UI
- **≤10 字**
- 大字、高对比，不玩花体
- 固定位置放系列角标

### 若走 Open Gate（原画幅直发）

竖屏平台上画面偏小，**上方留白带是关键资产**：
第一帧就放大字标题；下方留白保持空白（平台 UI 占用）。

## 三、开头（第一句 + 第一画面）

### 铁律

**不自报身份。**「大家好我是做 X 的」立刻掉完播。
身份靠简介承载（见 `2-ip.md`）。

**邀请绝不放开头。**片头一推销，完播率必掉。

### 第一句：六类句式库

卡住时从这里挑一句就开口。

**A. 具体时刻**（最安全，永远能用）
- 现在是[时间]，我在[地点]……
- 刚从___出来，路上想到一件事
- 今天第 N 个地方了，这是最后一站

**B. 反常**（最抓人）
- 这个我真没想到
- 本来今天休息的
- 说实话我今天挺意外的

**C. 直接抛问题**
- 有人问我___，我今天正好碰上了
- 你们猜这个多少钱

**D. 数字开场**
- 我算了一下，一共___
- 这个月第 N 次了

**E. 半句话（悬念）**
- 这个事儿……有点难讲
- 我先不说结论

**F. 场景白描**（适合 b-roll）
- 这条街我每周都要过好几次
- 你看这个位置

### 第一画面

要求：**有动作、不静止、不是人脸大头照**。

配合分镜的 3W 原则：开头常用**全景交代环境**或**特写抛出反常细节**，
不要用中景平铺直叙。

## 交付：多给，别只给一个

**用户来要标题，不是来给标题打分的。**
就算他贴了一个自己写的标题问「怎么样」——先给十个，再说他那个的问题。

| 给什么 | 至少 | 怎么给 |
|---|---|---|
| 标题 | **10 个** | 三种句式各 3 个以上，多平台时分平台各给一组 |
| 封面 | **3 个** | 取景描述 + 文字层，不是「拍得好看点」 |
| 第一句 | **5 句** | 覆盖不同句式，每句都能直接念出来 |

给完**排个序**，标出推荐哪个、为什么。**最终挑选权留给人。**

### 先读 learned

`profile.learned.works` 里已验证有效的句式**优先多给几个**；
`fails` 里证伪过的**不要再提**。见 `workflows/7-review.md`。

### 多平台

标题分平台各给一组——小红书 ≤20 字且关键词前置，
YouTube 和缩略图一起想。见 `references/platform-playbook.md`。

## ★★★ 封面与开头 —— 点击驱动平台的第一、二关，而且必须**看图**不能只看数

小红书和 YouTube 都是**点击驱动**（封面+标题决定点不点），抖音是信息流（不需要点击）。
所以在前两个平台上，漏斗顺序是：

```
1  封面 + 标题        点不点进来   ← 前面全白搭
2  开头 3–15 秒       留不留
3  选题              有没有东西可点、可留
4  关键词 / 描述       算法给不给量
5  b-roll / 视觉锚    几乎不影响前四关
```

⚠️ **不要把抖音的逻辑套到点击驱动的平台上** —— 那会让人把封面排到很后面。

### 一 · 封面：拼版直接看，统计量描述不了它

**做法**：同一频道内取播放最高 N 条和最低 N 条，各拼成一张图，**用眼睛看**。

| | |
| --- | --- |
| **必须同频道内比** | 跨频道比的是频道量级，不是封面 |
| **必须剔 Shorts** | 竖屏封面逻辑完全不同 |
| **必须拼版** | 封面是视觉的。「平均色相」「文字占比」这类指标**说不出差别在哪**，拼出来一眼就看见 |

#### 两个同题材频道实测（各 12 上 / 12 下）

```
✅ TOP   一张脸（作者本人）· 大 · 正面 · 有表情
        超大字压在上面（上排 4 字主题 + 下排具体）· 白/黄/红高对比
        实物（房子/地图/街景）只做背景

🔴 BOT   ① 纯物件照，无人无字
        ② 两个人对谈的截图 —— 小脸、小字，**像录屏不像封面**
        ③ 同一张底图套不同字 = **模板封面**
```

<sub>频道 A：top 中位 53,648 / bot 中位 30。频道 B：top 56,053 / bot 124。</sub>

⚠️ **「模板封面」和「固定版式」不是一回事，界限要划清**：

```
🔴 模板封面   同一张底图，只换字        → 观众一眼看出是批量货
✅ 固定版式   字体/颜色/位置/字号固定，
             **图每条不同**            → 一致性由字承担，识别度由图承担
```

★ **两个高分频道走的都是「固定版式」，而低分组里出现的是「模板封面」。**

### ★★ 二 · 问句放封面 ✅，放标题 🔴 —— 同一个元素，位置决定正负

| 位置 | 实测 |
| --- | --- |
| **标题**问号结尾 | **0.78×**（本人 111 条）· **0.68×**（频道 A）· **0.82×**（频道 B）—— 三方一致为负 |
| **封面**用问句 | 频道 B 的 top 12 张里 **6 张**是问句封面 |

**机制说得通**：标题里的问号占字数、且和搜索词不匹配；
封面上的问句是**视觉钩子**，直接制造好奇。

→ 处方：**问题放封面和口播开场，不放标题。**

### 三 · 开头：必须读字幕，标题层分析看不到它

🔴 **YouTube Data API v3 拿不到字幕**（`captions.download` 要 OAuth + 视频所有权）。
不补这一步，**所有对标结论都停在标题层** —— 而「点击后的开头」这一关一条数据都没有。

**补法**：`youtube-transcript-api`（抓 timedtext，不需要授权）。实测 23 条里 5/6 能拿到，
失败的是作者关了字幕（`TranscriptsDisabled`）。

#### ★★ 跨平台还原：用 YouTube 的字幕，读小红书拿不到的内容

小红书**只能拿到标题和评论，拿不到内容本体**。但——

```
在小红书看到一条爆款  →  找到同一个博主的 YouTube  →  拿字幕  →  读到那条内容到底说了什么
```

**同一个博主的同一条内容常常两个平台都发。**这是目前唯一能读到小红书内容本体的方法。

#### 开场实测（23 条同题材字幕）

```
★ 直接进话题   「今天这条视频我讲…」「接下来咱们看 XX 社区…」   —— 同题材最接近的对标全部是这一档，零自我介绍
  自我介绍     「大家好我是 XX」                              —— 另外几个频道
```

⚠️ n=23 且分布不均，**这是观察不是验证**。但它和「点击后第一句要回答『我为什么点进来』」一致。

★ **字幕还能看到标题层看不见的模板**：某频道 46 条「XX 社区 + 市场分析」是同一个句式开场
（「接下来咱们分析 XX 社区过去半年的市场情况」）—— **模板路在字幕里才显形。**
