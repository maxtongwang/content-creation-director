# 6 · 剪辑交付

**输入**：`script.yaml` + 实际素材 + `profile.yaml` 的 `styles` 段
**产出**：**两种，按用户选择**
- `edit-plan.json` —— 给自动剪辑工具执行
- `edit-sheet.md` —— 给人自己剪

---

## 核心原则

**AI 剪辑不该猜，它该执行。**

如果剪出来离想要的很远，问题几乎从来不在剪辑环节，
而在**脚本阶段的分镜没写完整**。回 `5-script.md` 补 `cut_reason` 和镜头表。

```
script.yaml（意图）→ 风格识别 → 素材打标（现实）→ 交付物
```

---

## 第一步 · 先识别风格（不能跳）

不同风格的剪辑参数完全不同。先确定这条属于哪种，再往下走。

```
1. topic-card 声明了 style      → 直接用
2. script 的 structure + form   → 反查 styles 表
3. 素材特征推断                  → 匹配最接近的
4. 都不确定                      → 问用户，不要猜
```

详见 `8-styles.md`。**识别不出就问，宁可多问一句，不要剪出四不像。**

拿到风格后，取出它的 `edit` 参数块：pace、avg_shot_sec、cut_density、
transition、bgm、subtitle、vo_handling、speed_ramp。**后面所有决策都受这组参数约束。**

---

## 第二步 · 素材打标

```
scene / subject / size / motion / audio / value / frame
speech（若为口播）: narrative | opinion | standard
```

打标方式：视觉模型 + 转写文本 + EXIF 三者结合，冲突时**以转写为准**。

---

## 第三步 · 口播驱动剪辑（主逻辑）

**不是按画面拼接，是按语义分段。**

```
1. 全量素材转写（含时间码）
2. 按语义切段 —— 对应脚本里的 vo_segment
3. 语义段 = 剪辑段，一段配 1–3 个 b-roll
4. 按 style.edit.vo_handling 处理口播
5. 口播断点即剪辑点，不在句中切
```

**禁止**：为凑时长重复 b-roll；为缩短时长砍掉完整语义段；按拍摄顺序排列。

---

## 第四步 · 镜头选取

```
优先级：
1. size + subject 与脚本完全匹配
2. cut_reason 成立（相邻镜头之间有信息/情绪/视角变化）
3. value=hero 优先于 broll
4. motion ≠ static（尤其 HOOK）
5. 单镜时长落在 style.edit.avg_shot_sec 区间内
```

**相邻两镜若 size 相同且 subject 相同 → 判为无效切镜**，合并或换镜。

---

## 分支 A · 交给 AI 剪辑

产出 `edit-plan.json`，结构见 `templates/edit-plan.template.json`。

关键：每个 shot 必须带 `cut_reason` 和 `in/out`。缺一个就退回脚本阶段补。

---

## 分支 B · 用户自己剪

产出 `edit-sheet.md` —— **人能看懂、能照着剪的清单**，不是 JSON。

```markdown
# 剪辑单｜<标题>
风格：<风格名>  节奏：<慢/中/快>  BGM：<有无及类型>
口播处理：<全保留 / 删长静默 / 紧凑>

## 时间轴

### 1. HOOK （目标 0:00–0:06）
- **声音**：素材 A012 的 3.2–9.8 秒（这句：「…」）
- **画面**：B003 特写，0–2.4 秒
- **为什么这么切**：信息改变（从环境切到细节）
- ⚠️ 注意：这一镜要够抓人，不够就换 B007

### 2. SETUP （目标 0:06–0:20）
...

## 必须保留
- vo-07 那句「不是每个单我都接」—— 这是信任来源，别剪掉

## 检查项
- [ ] 相邻镜头没有 size+subject 重复
- [ ] 邀请只出现在结尾
- [ ] 标题 ≤20 字（小红书）
- [ ] 底部没有重要信息被 UI 遮挡
```

**给人的版本必须包含「为什么这么切」**——否则他会按自己习惯改，
改完就偏离脚本了。给理由，他才会认。

---

## 分支 D · b-roll + 配音 全自动 → 见 `6b-autoedit.md`

`form = b_roll_vo` 且手上有素材库与剪辑软件的 MCP 时，走 `6b-autoedit.md`。

**这是产能最高的形态**——不用出镜、不用打光，素材可复用，配音可合成，
是全流程里唯一能端到端自动化的链路：

```
script.yaml → 配音 → find_broll 按段找素材 → edit-plan.json → DaVinci 搭时间线 → 通看 → 渲染
```

⚠️ 用 AI 合成配音之前**必须先过 `6b-autoedit.md` 第一节的判断表**——
合成音会同时冲掉 `self_presence` 和「人味儿即可信度」两条既有规则，
只有搜索型 / 攻略 / 榜单这类内容适用。

---

## 分支 C · 半自动

用户自己剪主线，AI 做粗剪。产出**两份**：
- 粗剪版 `edit-plan.json`（AI 执行，出一个粗剪）
- 精修清单 `edit-sheet.md`（只列需要人判断的地方）

适合大多数有经验的用户——**AI 省掉找素材和对齐口播的时间，人保留判断。**

---

## 出片前告警（不阻断，但必须列出）

| 告警 | 触发条件 |
|---|---|
| 风格不明 | 未能识别，且用户未指定 |
| 风格漂移 | 实际参数偏离 style 定义超过 30% |
| 无效切镜 | 相邻镜头 size + subject 相同 |
| 缺 cut_reason | 脚本里该镜头没写切镜依据 |
| 出镜不足 | b-roll 型不满足 self_presence |
| 底部遮挡 | `frame=bottom_busy` 且 `value=hero` |
| 身份不符 | 转写中出现 `forbidden_topics` 的词 |
| 邀请位置错 | 邀请类口播出现在 HOOK / SETUP |
| 标题超限 | 超出平台字数上限 |

---

## 永远保留人工的四项

**人在环上，不是人在环中。**

1. 隐私打码与授权（法律风险，不可自动化）
2. 态度类口播的语气匹配（语气错位会显得求人，机器判断不了）
3. 「表达标准」类内容的保留判断（误删即失去信任杠杆）
4. 最终成片的一次通看
