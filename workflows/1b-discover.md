# 1b · 素材挖掘（零基础用户专用）

**何时用**：用户说「我没什么好拍的」「我很普通」「不知道自己有什么」。

**问题所在**：`1-account` 的「先看自己有什么」对新手是死路——
他之所以来问，就是因为不知道自己有什么。

**解法：不要问「你有什么」，问具体的、有答案的事实。**

---

## 铁律

```
❌ 你的优势是什么？          → 答不出来
❌ 你有什么特别的经历？      → 「我很普通」
✅ 上周你花时间最多的三件事是什么？   → 一定有答案
```

**所有问题必须是「有确定答案的事实」，不是「需要自我评价的判断」。**

---

## 一、六个方向的事实挖掘

每个方向问 2–3 个具体问题，不做评价，只记录。

### 时间去哪了
- 上周花时间最多的三件事？
- 有没有什么事，你做的时间比周围人都长？
- 周末通常在做什么？

### 别人问你什么
- 最近三个月，有人问过你什么问题？
- 朋友遇到什么事会想到找你？
- 有没有什么事你解释过很多遍？

### 你的不满
- 你所在的行业/圈子里，什么事让你觉得离谱？
- 有没有什么「大家都这么做但其实不对」的事？
- 最近一次生气是因为什么？

### 你的代价
- 你为什么事付出过明显代价（钱、时间、关系）？
- 有没有什么坑是你踩过、别人还在踩的？
- 花过最不值的一笔钱是什么？

### 你的门槛
- 有什么事你做起来比别人省力？
- 有什么工具/技能你用得比周围人熟？
- 有没有什么资源是你有、别人没有的？（人脉、场地、设备、信息）

### 你的位置
- 你每天会经过哪些地方？
- 有没有什么场景是别人进不去、你能进的？
- 你身边有什么别人看不到的东西？

---

## 二、从事实到内容支柱

收集完事实后，做三件事：

### 第一步 · 找交叉
```
「花时间多」∩「别人会问」  → 强支柱（有兴趣 + 有需求）
「不满」∩「付出过代价」     → 强观点（有立场 + 有资格）
「门槛」∩「位置」           → 独家内容（别人拍不了）
```

### 第二步 · 反差检查
把事实两两组合，找**不该同时出现在一个人身上**的组合。

```
[身份 A] + [行为 B] = 反差
```

反差是最便宜的记忆点。这也是「惊世骇俗」类爆款的原理：
**你有一个点和 99% 的人不一样。**

### 第三步 · 可持续检查
对每个候选支柱问：**这件事你下个月还在做吗？明年呢？**

不在做的 → 只能当一次性选题，不能当支柱。

---

## 三、最小可行开始

新手最容易死在「准备阶段」。给一条**今天就能拍**的路径：

```
1. 从挖掘出的事实里，挑一件「今天正好会发生」的
2. 用最低成本形式：手机 + 一镜到底口播，或 b-roll + 配音
3. 不做封面设计，用现场最好看的一帧
4. 发出去，不改
```

**第一条内容的目的不是爆，是打破「还没准备好」的循环。**

告诉用户：起号是一夜之间，不是日积月累。
一条数据不好就换方向，不要坚持。

---

## 出口

产出一份**候选支柱清单**（3–5 个），带：
- 支撑它的具体事实
- 归到 A/B/C 哪层
- 能不能持续

然后回 `1-account` 继续填 `profile.yaml`。

---

## ★★ 未挖矿脉审计 —— 把 profile 和选题库做交叉

**做完选题库之后必跑一次。**列出 `profile` 里**有事实、但零选题引用**的条目。

| 步 | 动作 |
| --- | --- |
| 1 | 把 `profile` 里所有具体事实抽成一张清单（地点、物件、频率、日期、关系、职业细节） |
| 2 | 逐条去选题库里搜：**有没有任何一条选题用到它** |
| 3 | 零引用的 = 矿脉。按「具名地点 / 可讲的数字 / 供给稳定性」排序 |
| 4 | ⚠️ **同时标出「坑」** —— `profile` 里明写「不做」或标着 `[推断] 待验证` 的，**不开采** |

**为什么必跑**：编导写选题时会不自觉地围着**最近讨论过的**几个事实转，
`profile` 里躺着的其他事实就一直躺着。**一次交叉能翻出一整条内容线。**

真实一轮的产出：六条零引用事实里，**三条直接开成一条新内容线**——
其中最好的一条，`profile` 里甚至已经写明了它的价值（「它不是 X 内容，是**本地**内容」），
**但没有任何一条选题用过它。**

⚠️ **坑要一起标出来。**同一轮里两条零引用事实是明确不能开采的：
一条 `profile` 写着「有能力，但不做」，一条标着 `[推断] 待验证`。
**零引用不等于该用。**

## ★★ 该问的时候要问 —— 一次访谈胜过十轮推断

一个真实对照：

```
基于 profile 推断产出的选题库   367 条 → 三闸门全过 1 条（0.3%）
一轮五个问题换来的             2 条新内容线 + 3 处事实纠正 + 全库最强的单条
```

**原则七说「不要求用户先填齐再开工」——那说的是不要用表单挡住开工，
不是说永远不问。**榨干已有信息之后，**该问就问**，而且要问对：

| 问法 | 效果 |
| --- | --- |
| ❌ 「讲讲你的经历」 | 得到简历，不是故事 |
| ✅ **「那一天发生了什么」** | 得到事件锚（[闸门四](#)）、具体对象、真实情绪 |
| ✅ **指着 profile 里的 `<待补>` 问** | 用户知道你读过，答得具体 |
| ✅ **问一个你推断过、但标了 `[推断]` 的** | 常常直接推翻推断 |

⚠️ **推断错了要当场改，并说清楚故事因此变了什么。**
真实一例：profile 假设「他在来这座城之前那一年在别处」——
真相是**他一来就在这儿，那一年在中间**（中途去外地一年，毕业就回来）。
数字口径一个没变，**但故事从「一直在」变成了「离开过又回来」——后者强得多。**

### 「后悔」有两个方向，默认问错了一个

编导默认问「你**做错**过什么」（commission）。但很多人真实的后悔是
「我**没做**什么」（omission）—— 尤其是运气不错、决策记录良好的人。

```
❌ 我最后悔做过的三件事      用户回：「运气好，没做过什么后悔的动作」→ 整条线作废
✅ 我没做错什么，但有三件我没做   同一个人，立刻有话说
```

**问之前先确认方向**，否则会做出一整条用户答不上来的内容线。

### 用户说「这条可以放弃」，就放弃

用户对自己素材的判断优先于编导的结构偏好。
真实一例：一个「每周固定的多人场景」在结构上非常适合做系列
（稳定、有人物、零外勤），但用户说**「很难出有深度的内容，可以考虑放弃」**——
**删掉，不要因为它填满了一个格子就硬做。**

### 「不上镜」经常是形态问题，不是意愿问题

家人 / 伙伴不肯出镜时，先分清是**不愿意**还是**不自然**。

```
不愿意  → 边界，尊重，不再问
不自然  → ★ 形态问题，有解：改对谈
```

**对谈让注意力离开镜头**——有人对话，人就不用面对机器。
一个真实用户主动给出的解法就是这个：「她拍视频主要是不自然……可以对谈形式」。
⚠️ 对谈是**第三种形态**，剪辑参数与口播、图文都不同，要单独在 `8-styles` 里定义。

## ★★★ 一句个人事实 ≈ 一条内容线（兑换率是可以量出来的）

一个真实项目的完整对照：

| 来源 | 产出 | **三闸门合格率** |
| --- | --- | --- |
| **基于 `profile` 推断**产出的选题库 | 367 条 | **1 条（0.3%）** |
| **用户陆续给出的个人事实** | **65 条 · 12 条线** | **65/65（100%）** |

**不是推断能力不够，是推断产不出「形状」。**

### 每一句事实换到了什么

| 用户给的一句话 | 换到 |
| --- | --- |
| 转行那天的具体经过（时间 + 冲突对象 + 触发动作） | **一整条线 9 条，含全库第一名** |
| 配偶的职业与「拍视频不自然」 | 4 条 + **一个全新的呈现形态（对谈）** |
| 持有的四处资产 | 9 条 + 补上最大的地名缺口 |
| 「我做过一个工具，还有很多想做但没做」 | 4 条 + 一个闸门物 + **内容与闸门同时增长的机制** |
| 一桩正在进行的交易 + 家人给的两条禁令 | 6 条 + **第一个真闸门**，且禁令本身成了最强的一集 |
| 孩子的年龄 | 3 条 + **让一条长连载的终点可计算** |

### ★ 最值钱的不是「他做过什么」，是「那件事的具体形状」

```
❌ 标签   「他从工程师转行做经纪」                        → 出不了选题
✅ 形状   「某年某月，因为忙和父亲大吵一架，
           当晚算了一遍现金流，第二天原地辞职」           → 一条线 9 集
```

**同一件事。标签是可推断的，形状必须问。**
而[闸门四（事件）](#)要的就是形状 —— 这解释了为什么推断出来的选题过不了事件闸门。

⚠️ **`profile` 要记形状，不要记标签。**
一份全是标签的 `profile`（「职业路径：先做 X 再做 Y」）看起来很完整，
**但一条选题都长不出来。**每条事实后面追问一句「**那具体是哪一天、发生了什么**」。

### ★★ 每一批新事实都会推翻一个推断 —— 所以推断必须可撤回

同一轮里被推翻的（**全部**是我此前写进 `profile` 的推断）：

| 我推断的 | 真实的 |
| --- | --- |
| 「他在来这座城之前那一年在别处」 | **一来就在这儿，那一年在中间** |
| 资金链条是「启动金 → 股市 → 地产」 | **启动金 → 地产 → 股市（用途是换自住）** |
| 「我最后悔做过的三件事」 | 他没有后悔的**动作**，只有没做的事 |
| 超级符号是标题里的标签 | **是一句口播台词** |
| `profile` 里两处年龄并存，我按较大的那个理解 | **较大的那个根本不是他的年龄，是一句引语** |

**处方**：
| | |
| --- | --- |
| 推断一律标 `[推断]` | 并写清**推法** —— 否则无法验证，也无法撤回 |
| 被推翻时**当场改，并说清故事因此变了什么** | 常常数字口径一个没变，**故事强度差一个量级** |
| 🔴 **引语不要写成事实** | 真实事故：一句「有人说我都 44 了」被记成了年龄，
  差一点让 agent 写出硬错误。**引语必须标 `引语`** |

### 怎么问：顺着他已经给的往下挖一层

**产出最高的回答，往往不是回答我问的那个问题，是他因为被问到而主动补的下一句。**

| 我问 | 他答 | 我追问 | **真正的产出** |
| --- | --- | --- | --- |
| 有什么正在进行的事 | 一桩交易 | 能说到什么粒度 | **家人给的两条禁令** ← 最强的一集 |
| 转行的契机 | 工作太忙 | **那一天发生了什么** | **和父亲大吵 → 当晚算账 → 次日辞职** |

**追问模板**：
```
那具体是哪一天？            → 事件锚
当时那个东西/那个人是什么？   → 对象
你当时做了什么动作？         → 从想法变成事件
有没有什么是你不能说的？      → ★ 限制本身经常是最好的一集
```

★ **最后一问最容易被跳过，但回报最高。**
「什么不能说」问出来的不只是边界 —— **一个「我不能说价格」的限制，
本身就是一个有对象、有情绪、有对手的完整选题。**

## ★★ 事实文档和方法文档必须分开 —— 理由不是整洁，是事实会漂移

一个项目通常会有两份长文件：**`profile`（这个人是谁）** 和 **选题库（拍什么）**。
编导写选题时会很自然地把用到的事实**顺手抄进选题库**，让那一段读起来完整。

**这是个会造成实际损害的错。**

真实事故：同一个年龄，一处被记成「本人属性」，另一处被记成「别人说的一句话」。
两份文件都没写错，**但框定方式不同 —— 差一点让 agent 把一句引语当成本人年龄写进口播。**

```
事实存两处  →  两处会各自演化  →  框定漂移  →  agent 取到哪一份看运气
```

### 职责怎么切

| 文件 | 存什么 | 不存什么 |
| --- | --- | --- |
| **`profile`** | **唯一事实来源** —— 谁、什么时候、多少、**能不能说** | 论证过程 |
| **选题库** | 选题 · 判断 · 论证 · 数据依据 | **任何事实**（一律引用，不复制） |

⚠️ **「能不能说」跟着事实走，不跟着选题走。**披露规则和它约束的那条事实
**必须在同一个文件里** —— 分开就会有人只读到事实、没读到规则。

⚠️ 一次真实清理：从选题库里删掉 **410 行**重复的个人事实，
选题和论证一行没少。**那 410 行从来没提供过信息，只提供了漂移的机会。**

---

## ★★ 收精确日期，不要收年龄

用户会自然地用约数说自己：「二十五岁结婚」「二十八岁有的孩子」。**照单全收会出两种问题。**

### 一 · 约数会让时间线算错

一个真实对照（同一个人，同一批事件）：

| 用户口述 | 按精确生日实际 |
| --- | --- |
| 25 岁结婚 | **24 岁** |
| 28 岁第一个孩子 | **27 岁** |
| （编导据此推的）现在 36 | **35 岁** |

三处全差一岁。**单看无所谓，但连载的进度是靠时间线算的** ——
「这个终点还有几年到」差一岁就是差一年的内容规划。

### ★★★ 二 · 日期之间会产生关系，年龄不会

这是更重要的那个理由。

```
年龄   31 岁 · 6 岁              两个独立的数，什么都不产生
日期   01-20 · 01-20            ★ 同一天 —— 一条内容自己长出来了
```

真实一例：收了精确生日之后才发现**配偶和儿子同一天生日**。
这类事实：**真实 · 有情绪 · 每年自动复发 · 零制作成本** ——
而**收年龄永远发现不了**。

**要找的关系**：同一天 · 相差一天 · 同月 · 与某个事件重合 · 整十周年将至。

⚠️ 所以 `profile` 里的人物字段应该是 `birthday: YYYY-MM-DD`，**不是 `age: N`** ——
年龄每年都会过期，日期不会，而且日期能算出年龄，反过来不行。

## ★★★ 叙事型内容线：先建时间线，再写选题

一个真实项目里，同一条内容线的**性质被改写了三次**，每次都是因为补进了新的时间信息：

| 轮次 | 补进什么 | 那条线从 → 变成 |
| --- | --- | --- |
| 1 | 资金的真实先后顺序 | 「靠副业赚到本金」→「本金一开始就投在了这里」 |
| 2 | 离开前的职级晋升速度 | 「干不下去了」→ **「刚证明能爬得比别人快，然后走了」** |
| 3 | 离开前 12 个月的资产动作 | 「一时冲动」→ **「铺了整整一年，那天只是扣扳机」** |

**三次都不是事实错了，是事实不全。**
而每一次改写，**之前写好的钩子和第一句都作废了。**

### 规则一 · 时间线没填满之前，不要定稿任何叙事型内容线

```
❌ 先写选题 → 边写边补事实 → 每补一次重写一批
✅ 先填「哪一年发生了什么」这张表 → 表满了 → 再写选题
```

⚠️ 判断标准：**这条线上每一年都能说出一件具体的事吗？**
有空档就先问，不要用「大概那几年」糊过去。

### ★★★ 规则二 · 导火索 ≠ 原因 —— 主动问「那件事之前一年」

**用户会自然地讲导火索，因为那是他记得最清楚的一幕**（一场争吵、一通电话、一个数字）。
**但导火索单独讲，人物会变成一个冲动的人 —— 而冲动的人不可信。**

真实一例：
```
用户讲的      「因为一件事跟家人大吵，第二天就辞职了」
实际发生的     前一年里已经做完了四件铺路的事，那天只是扣扳机
```

**追问模板**：
```
那件事之前一年，你在做什么？
在那之前，你有没有为这个做过什么准备？
如果那天没吵那一架，你还会走吗？    ← 最锋利的一问
```

⚠️ 最后一问的答案，往往就是**这条线真正的第一集**。

### ★★ 规则三 · 顺序即论点 —— 播出顺序要写进选题库

同一批内容，顺序不同，观众得到的结论不同：

```
「怎么爬上去的」在前 → 后面的离开读作 选择
「为什么离开」在前   → 读作 逃离
```

**这不是排期偏好，是论点的一部分。**
⚠️ 内容线之间的**顺序依赖必须显式写在选题库里**（「M 必须排在 I 之前，反了就白讲」），
**不能靠拍摄时临场判断** —— 到那时写选题的人已经不在了。

### ★ 规则四 · 问顺序，不只问内容

**「他做某件事的顺序和大多数人相反」是最强的反差单点之一**，
而且**只有主动问顺序才会浮出来**。

真实一例：问「你有哪些资产」得到一张清单；
问「哪个是第一个」才发现 —— **他的第一处房产不是自住的，是投资的。大多数人反过来。**
那一条的下限分直接满分。

```
❌ 你有什么          → 清单，没有反差
✅ 哪个是第一个       → 顺序，可能藏着反差
✅ 那时候大多数人怎么做 → 把反差量出来
```

## ★★ 不可分享的事实，往往是可分享事实的上游

用户说「这个不要讲」时，编导默认的处理是**从选题里排除掉**。**不够。**

**不可分享的事实很少是孤立的，它和可分享的事实之间常有因果链** ——
只删不设防，**观众会把话题推回去**。

真实一例：
```
✅ 可讲   多年后的一场家庭冲突（一条内容线的核心）
🔴 不讲   多年前同一段关系里的另一件事
```
两者之间隔着一条七年的关系线。**只要那条线讲深了，评论区必然会问回去。**

### 处方：护栏 + 预设止损

| | |
| --- | --- |
| **护栏** | **只讲可分享的那一段，不往回连。**一往回连就需要讲不能讲的部分 |
| **预设止损答复** | **提前备一句，不临场发挥。**例：「这个我就讲到这儿。」 |
| 找法 | 拿到「不可分享」的事实后，问自己：**哪条已定选题的追问方向会撞上它？** |

⚠️ 临场发挥是最危险的 —— 被追问时人会本能地多解释一句，**而那一句往往就越界了。**
