# 3 · 选题决策

> ⚠️ **本文里的倍率都是 📊 = 样本，不是常数。**它们证明「那个测法能测出东西」，**不代表你的账号会得到同一个数** ——看 🔬 测法，用自己的数据重跑。见 `SKILL.md` 原则三十四。

**输入**：`profile.yaml`（没有就先回 1-account）
**产出**：`topic-card.yaml`
**方法论**：`references/method-viral.md`、`references/method-account.md`、`references/hot-and-language.md`

## 先生成，再筛

**用户来要选题，不是来给选题打分的。**
就算他只带来一个想法问「这条行不行」——先生成一批，再把他那条放进去一起比。

```
选题生成  →  定位闸门  →  爆款增幅  →  验证  →  排序交付
（大量做）    （滤掉不能做的） （放大）    （筛）    （给 8 个）
```

**闸门是筛选器，不是入口。**先有东西才谈得上筛。
但闸门本身不放水——滤掉就是滤掉，不为了凑数放行。

**定位是闸门，爆款是放大。**爆款元素只能在定位允许的范围内放大，没有改写定位的权力。

### 开工前先读 learned

`profile.learned` 是历次复盘验证过的结论，**这是 skill 变准的地方**：

| 读什么 | 怎么用 |
|---|---|
| `works` | 验证有效的方向和句式，优先多出几个 |
| `fails` | 证伪过的，**不要再提** |
| `audience.常问` | 观众反复问的问题，**天然选题库**，直接拿来用 |
| `open_questions` | 待验证假设，可以设计一条内容去验它 |

没有 `learned`（第一次用）就跳过，正常生成。

## 零、选题的四个来源

**「给我几个选题」不该只靠模型想。**四个来源，能取几个取几个：

| 来源 | 拿什么 | 怎么取 |
|---|---|---|
| **你是谁** | 定位、支柱、禁区、验证过的 `learned.works` | `profile.yaml` |
| **观众要什么** | 评论区反复问的问题 | `learned.audience.常问`；有 MCP 就 `get_feed_detail` 读评论 |
| **平台现在在推什么** | 同赛道当下的排名与量级 | `search_feeds` / `videos_searchVideos` |
| **你拍得出什么** ★ | 素材库里已有的画面 | `search_clips` / `find_broll` |

### 第四个来源最容易被忽略，但最实用

**素材库决定哪些选题今天就能做，哪些要等拍摄。**
每个候选都标一句：

```
[今天能做]  素材库里有对应画面，直接进 5-script → 6b-autoedit
[需补拍]    要拍什么、几个镜头，进 shoot_needed
```

一个「今天能做」的普通选题，价值经常高过一个「要拍三天」的好选题。

### 关于「最近热门」——先说清楚能做到什么

**没有热榜接口。**能拿到的是「现在搜这个词，排在前面的是什么」，这是代理指标，不是热榜。

| 平台 | 能拿到 | 可信度 |
|---|---|---|
| YouTube | `videos_searchVideos` 支持 `publishedAfter` + `order`，**能查「近 14 天内发布、按播放排序」** | 高，是真实的近期表现 |
| 小红书 | `search_feeds` 看某关键词当下的排名与互动量级 | 中，是排名不是热度 |
| 小红书 `list_feeds` | 首页推荐流 | **低——这是推给你的，不是全网热的** |

**`list_feeds` 的偏差要主动说明**：它是按你的账号画像推的，
拿它当「大家都在看什么」会把你自己的兴趣误当成趋势。

**没有工具时不要停**——凭 profile 和方法论照常生成，只是少了现状校准。

### 第四来源查完要给结论

检索**命中为 0** 时，含义不是「这个来源没用上」，而是
**「本轮全部选题都是需补拍」**。

此时**必须先排补拍，再排选题**——否则会出现「选题一大把，一条也发不出去」。

### 选题库是存量，四来源是流量

| | 性质 | 正确用法 |
|---|---|---|
| 选题库 | **存量**，用完就没 | 本周流量不够强时**调一条救场** |
| 四个来源 | **流量**，每周自己长 | 主力 |

拿存量当主力，两个月后就空了，而且空的时候毫无预警。

## ★ 选题卡最小字段集（每条都要有，缺一项就是没跑完）

**这一节是 `method-account` 与 `method-viral` 的必做项的合并清单。**
以前它们散在两份文档里，结果是「知道有这回事，但每次都漏几项」。

```
□ 选题                该拍什么
□ ★★ 对象            这条里那个具体、外部、可辨认的东西 —— 填不上就不拍
□ ★★ 挑人度          通 / 半 / 独 —— 换个人还能不能拍
□ 内容线 / 形态        属于哪条线，怎么拍
□ ★ 爆款元素          八标签命中哪几个 —— 一个都没命中 → 重做
□ ★ 爆款类型          万古同悲 / 惊世骇俗 / 打破节奏，挑一个主打
□ ★ 四条件            ①看得懂 ②群体够大 ③情绪或信息 ④能引发互动
□ ★ 作品目的          数据型 / 涨粉型 / 商业型 / 调性型 / 表达型
□ ★ 脚本结构          讲故事 / 晒过程 / 教知识 / 聊观点 / 尬段子 / 说产品
□ ★ 呈现形式          口述 / 视频+配音 / 图片+配音 / 情景剧
□ 闸门结果            命中哪条禁区，或为什么放行
□ 四来源标注          ✅🟡❌ 逐一
□ 今天能做 / 需补拍    素材库查过没有
□ 平台                多平台用户必给
```

### 带 ★ 的六项最容易被漏

它们全部来自那两份方法论，而**不在多数人记得住的清单里**。
其中三项的判据是硬的：

| 字段 | 硬判据 |
|---|---|
| **对象** | **填不上 → 不拍**（见下一节） |
| 爆款元素 | **一个都没命中 → 重做**，不是「可以再想想」 |
| 四条件 ② | 群体够大 —— **这是唯一真闸门**。太窄的降级为弹药，招错人的只当背书 |
| 作品目的 | **起号期优先涨粉型**。全是数据型 → 只涨收藏不涨关注 |

## ★★ 三个可以自己算的闸门

**编导有两件事要做：了解这个人，和给这个人客观工具。**
下面三项是**用户自己就能算的**，不需要相信编导的判断。

### 一 · 对象测试 —— 这条里那个具体、外部、可辨认的东西是什么

```
一个数字 · 一个地方 · 一群人 · 一件物 · 一个变化
```

**答不上来 → 不拍。**没有对象的内容只有「我今天去了哪儿、我怎么想」，那是流水账。

📊 一个真实小账号（111 条，已剔离群值）的头尾对照：

| | 有对象 | |
| --- | --- | --- |
| 头部 7 条 | **7 / 7** | 一个吓人的数字 · 我家 · 一群人 + 一个变化 · 一个职业转折 · 一个具体社区 |
| 底部（≥5 分）7 条 | **0 / 7** | 只有「我去了哪儿 / 我怎么想」 |

头部那 7 条**长度从 18 秒到 8 分都有，vlog 与非 vlog 都有** ——
**形式不是变量，有没有对象才是。**

> 它和 `method-account` 的转化触发条件是同一条：
> **具体、可辨认的对象（地点 / 物件 / 型号）**。
> 那一节讲的是它决定转化；这里补一句：**它同时决定分发。**

### 二 · 挑人度 —— 换个人还能不能拍

`method-viral` 第七节分了 **IP 型**与**内容型**两种博主，但没给可操作的判据。补上：

| 记号 | 含义 | 性质 |
| --- | --- | --- |
| **通** | 换个处境相同的人也能拍 | 拿得到分发 |
| **半** | 需要一段普通人都有的经历（后悔过、选过、错过） | 中间态 |
| **独** | 需要这个人独有的履历事实 | **互动质量高，但拿不到分发** |

📊 实测（同一账号，n=1，只当方向）：个人故事簇**中位评率是全站的 4.1 倍**，但中位曝光是全站最低那几档。

```
挑人的内容    互动质量高，分发差
不挑人的内容  分发好
```

**处方不是二选一，是：用不挑人的选题 + 这个人自己的表达。**
人设从**怎么讲**里渗出来，不用把履历塞进选题 —— 这正是「人格是副产品」。

⚠️ **独** 那一档不要清零：它是互动质量的来源。但**不能当主力配额**，
否则内容会变成「必须先认识这个人才看得懂」。

### 三 · 事件测试 —— 这一集挂在**哪件发生过的事**上 ★ 最强的一条

对象测试问「有没有一个具体的东西」，事件测试问**「那个东西身上发生了什么、什么时候发生的」**。

```
对象   这一集里那个具体、外部、可辨认的东西        —— 名词，静态
事件   那个东西出事的那一天                       —— 动词 + 时间锚，动态 ★
```

用户原话：**「能够让内容有一定长度和深度的，永远是事件激发表达欲，
能够发表个人的经验、感想、思想。这样才可以减少准备时间。」**

#### 实测：一个 218 条的真实频道，按标题能否指认一件发生过的事分组

| | n | 中位时长 | **≥5 分占比** | 每千曝光评论 | 零评论率 |
| --- | --- | --- | --- | --- | --- |
| **事件型** | 88 | **353s** | **57%** | **10.55** | 36% |
| 资料型 | 11 | 160s | 9% | 7.56 | 36% |
| 概念 / 状态型 | 119 | 190s | 27% | 8.74 | **47%** |

剔掉 <60 秒短视频这个混淆项后效应更大：事件 **387s / 62%** vs 资料 **164s / 11%**。

```
长度   事件型自己长出 2.2 倍，≥5 分钟的比例是资料型的 6.3 倍   ✅ 干净、量大
深度   每千曝光评论 1.22–1.40×，零评论率低约 11 个点          🟡 弱，同向
流量   ❌ 不成立
```

#### 🔴 不要拿这条当爆款理由

六个频道横测事件/资料中位播放比：**1.32× · 1.01× · 9.23× · 1.73× · 0.99× · 0.64×**。
最后一个反着来。**事件型换的是长度和准备时间，不是播放量。**
和「对象测试」不同 —— 对象决定分发，**事件决定成本**。

#### 真正的理由：准备时间决定了能不能持续更新

| 类型 | 开拍前要做什么 | 能不能高频 |
| --- | --- | --- |
| **事件型** | **回忆。事已经发生了，观点是现成的** | ✅ |
| 概念 / 状态型 | 现场想观点、搭结构、举例子 | 🔴 每条都是一次小写作 |
| 资料型 | 查资料、核数字、列提纲 | 🔴 定死低频（见 `8-styles` 第零节） |

**「减少准备时间」不是效率优化，是能不能维持更新频率的前提。**
一个选题库看着条条都对却拍不动，机制通常在这里 ——
**它把「想清楚一件事」的成本，全留在了开拍那一刻。**

#### 改写：概念型 → 事件型

只加一件东西：**一个时间锚（那天 / 上周 / 昨天 / 上个月）+ 那天发生的动作。**

| ❌ 概念型 | ✅ 挂上事件 |
| --- | --- |
| 我为什么留在这座城 | 上周我带人看了三个城，回来路上想通了我为什么没搬走 |
| 某项开支为什么在涨 | 我这张账单今年涨了，我打电话问了为什么 |
| 转行的思考 | 昨天有人问我后不后悔，我当场没答上来 |

#### 定档闸门（三问，缺一条不拍）

| | 问 | 不过怎么办 |
| --- | --- | --- |
| 1 | **哪件事？发生在什么时候？** | 想不出具体那天 → 退回，或等它真的发生 |
| 2 | **这件事让我想说的那句话是什么？** | 说不出 → 是资料型，走低频形态 |
| 3 | **开拍前我需要查东西吗？** | **需要 → 不是这周拍的** |

⚠️ 第 3 问是硬闸门。**「需要准备」和「高频更新」不能同时成立。**

⚠️ 选题库要统计事件率。**低于 50% 就是一个拍不动的库** ——
不是选题不好，是成本被推到了错误的时点。

#### 🔴 纯概念 / 状态型：默认不产出

**「我怎么看 X」「X 是什么样的」「关于 Y 的思考」—— 这一类默认不进选题库。**
不是因为它们不好，是因为它们**把全部成本推到开拍那一刻**，而用户在那一刻会跳过它。

放行的唯一条件是**至少能挂上下面一项**：

| 挂上什么 | 长什么样 |
| --- | --- |
| **事件** | 有一个时间锚 + 那天发生的动作 |
| **经验** | 有一个「我试过、代价是多少」的具体结果，不是观点 |
| **能激发分享** | 观众看完有话要说、有立场可站、有人可以 @ |

三项全无 → **不写进库。**写进去只会稀释库的可执行率。

### 按线定，不逐条标

同一条内容线里，**作品目的 / 爆款类型 / 脚本结构 / 呈现形式基本是一样的**。
在内容线上定一次，线里的每条继承 —— 逐条标几十次是重复劳动，而且会标得不一致。

**例外**：走机动位的一次性弹药**必须单独标**，它们不属于任何线。


## ★★ 三维打分：选题排序（不是选题生成）

**闸门决定「能不能发」，打分决定「先发哪条」。**两件事，不要混。

### 🔴 只按流量打分，会把账号带偏

真实失效记录：我给一个服务型账号的全部选题打了**流量分**（群体 + 爆款类型 + 对象 + 标题）。
然后按分数反推，又生成了一整组高分选题 —— 结果那一组长这样：

```
我最狼狈的一次 · 我最后悔的三件事 · 我学不动了 · 我最没底气的那一年 · 我这行最不体面的一天
```

**流量分全组第二高。**但对一个卖服务的人来说，
**这不是人设，是简历上的减分项** —— 而流量分完全看不见这一点。

### ⚠️ 流量分 = 下限分，不是预期播放量

八个真实频道实测：**相邻两条播放量的自相关中位 0.06** ——
「上一条的真实成绩」这个信息量最大的预测源，对下一条只解释 **0.4% 的方差**。
**流量本身不可预测。**

所以流量分打的**不是「这条能跑多少」，是「这条的下限有多高」**。
抬下限的特征（第一人称 / 地名 / 足够时长 / 事件）和造爆款的特征**会互相打架** ——
详见 `7-review`「流量不积累」。

### 三个维度

```
综合分 = 流量 × 0.4  +  变现 × 0.3  +  人设 × 0.3       三项各 0–10
```

| 维度 | 问什么 | 主要成分 |
|---|---|---|
| **流量** | 这条能跑多大（**天花板**） | 群体大小（唯一真闸门）+ 爆款类型 + **有没有对象** + 标题因子 − 执行性扣分 |
| **变现** | 对**变现人设**有没有帮助 | **有没有闸门（权重最大）** + 离生意多近 + 是否筛出可能成为客户的人 − 招同行 |
| **人设** | 这条累积起来把他塑造成谁；**积不积极** | 离「他真实在过的好日子」多近 − 负面/自贬词 + 正向词 |

**第三维的本质**：`W009 人格是副产品` 的打分化 ——
**内容不是描述人设，是塑造人设。**一条一条累积起来的那个人，才是观众看到的人。

### 三条实践规则

| # | |
|---|---|
| **1** | **三个维度的冠军通常互不重叠。**实测：流量冠军是「大群体 + 地名」组，变现冠军是「晒过程 + 闸门」组，人设冠军是「他真实在过的日子」组 —— **单一维度的最优解不是全局最优** |
| **2** | **人设分 ≤2 的内容，每 10 条最多 1 条**，且那一条**必须有收束**（「后来我改了什么」），不能停在惨上 |
| **3** | **变现维度里闸门权重最高。**没有闸门的内容，变现分天然低 —— 这与「转化 = 闸门」一致，不是 bug |

⚠️ **不要用综合分决定「删不删」，只用它决定「同一格里先发哪条」。**
低分往往是**服务另一层漏斗**的内容（见 `method-account` 运营漏斗）。

### 怎么落地

**分数必须能重算，否则它只是编导的偏好。**
每个系数都要指向一条可查的实测；组级人工项要单独列出并说明理由。
**做成脚本，改了选题就重跑 —— 不要手改分数。**

## ★★★ 从评论区挖选题 —— 「观众要什么」这个来源的唯一可操作解法

`3-topic` 四来源里，「**观众要什么**」是最常被跳过的一个 ——
因为它听起来像「多读评论」，而那不是一个动作。**这一节把它变成动作。**

### 为什么它值得单列

一个真实项目：账号断更一年多，**自己的评论区是干的**（170 条评论里只有 1 条真实商业需求）。
但**别人的评论区不是** —— 32 篇他人笔记换来 580 条一级评论，
其中「城市怎么样」被问 30+ 次、「怎么挑经纪」15 次。

```
自己的评论区   告诉你「你的观众是谁」   —— 断更时是干的
别人的评论区   告诉你「市场在问什么」   —— ★ 任何时候都能采
```

⚠️ **两批不能混用，而且引用时句式不同**：

| 来源 | ✅ 能说 | 🔴 不能说 |
| --- | --- | --- |
| 自己评论区 | 「有人问我 X」 | — |
| **别人评论区** | 「这个问题我看到很多人在问」 | **「有人问我」—— 那不是问你的，是编造来源** |

### 🔴 不要用点赞数筛问题

直觉是「赞少的没人关心」。**实测反过来：**

```
YouTube 中文地产 424 条评论
  提问型 n=124   中位赞 0    中位回复 1.0
  非提问 n=300   中位赞 1    中位回复 1.0
```

**提问型评论的中位赞是 0。**因为点赞是给「说得对」的，不是给「我也想问」的 ——
**想问的人用回复表达（「蹲」「+1」「我也想知道」）。**

实例：`0 赞 4 回复` 的「Rancho Cucamonga 治安好吗？宜居吗？」——
**用赞数筛会直接丢掉，用回复数筛能抓到。**

### 正确的三个筛子（两个平台的 API 都给这些字段）

| 筛子 | 权重 | 为什么 |
| --- | --- | --- |
| ★★★ **回复数**（`subCommentCount` / `totalReplyCount`） | 最高 | **提问型的原生互动信号** |
| ★★ **赞数 ÷ 该篇总赞** | 中 | 归一化，去掉「大号笔记下的评论天然赞多」这个混淆 |
| ★ **同一篇内的相对排名** | 低 | 去掉位置效应（排前面的天然多赞，热评置顶后滚雪球） |

⚠️ 三个都不要用绝对值。

### 挖到之后，怎么判断哪条能做

**筛子是「能不能用第一人称经历回答」，也就是[事件闸门](#)：**

| | 例 | 处置 |
| --- | --- | --- |
| ✅ **能用亲身经历答** | 「XX 城怎么样」（他住过 / 持有过） | 做，事件型 |
| 🟡 **要查表** | 「哪些城市地税低」 | 资料型 —— 低频，且必须[大白话 + 有例子](#) |
| 🔴 **是在找服务不是问问题** | 「报价多少？可以给个地址吗」「有没有好房源介绍」 | **跳过** —— 答它就变成广告 |

### ★ 回复优质评论，比挖问题更强

```
挖问题    我看到很多人在问 X       素材，但没有对手
回评论    有人说 Y，我不同意        ★ 有对象 · 有对手 · 有事件锚 —— 三道闸门一次全过
```

而且它天然落在「**我遇到过 / 我也纠结过 / 有人问我**」那一档，
不会滑向「我来告诉你」。

### 做成定期，但别挂 cron

```
✅ 一条命令 + 状态文件（问题指纹去重 + 已抓笔记，断点续跑，只报新增）
🔴 不要挂 cron —— 需要登录的平台 cookie 会过期，挂了会静默失败，
   你以为它在跑，其实几周没数据
```

**没登录时脚本要直接停下并打印重新登录的方法，不要假装成功。**
⚠️ 采集时**务必存来源 ID** —— 一次真实教训：580 条评论采完没存 note id，
想回原帖核对都找不到。

### 把问题做成画面：仿真评论卡

内容里要展示「这个问题很多人在问」时，做一张**仿评论区样式的卡片**。

| | |
| --- | --- |
| ✅ 合法 | 问题**原文一字不改** · 观众**看得出是做的卡片**（不伪装成截图）· 标明来源平台 |
| 🔴 不合法 | 用**真实存在的昵称/头像** —— 唯一会出事的地方是撞上一个真账号 |
| ⚠️ 细节 | IP 属地：**海外只显示国家**，不显示州/城市 |

★ 一集讲一个问题 → **一张卡一个评论**，按视频画幅出图（如 1280×720），
截图 / 打印导 PDF / 录屏都能用。**它不是 b-roll，是一张图，零剪辑成本。**

## 一、生成 · 选题两步法

### ⚠️ 涉及本人经历的选题，先核对事实

任何以「我曾经…」「我从…转到…」为前提的选题，
必须先查 `profile.ip_analysis`（职业路径 / 最骄傲的事 / 最挫折的事 / 缺点）。

**不可从公开数据推断本人经历。**推断出的前提会让整条选题作废，
而且用户要花时间纠正——**这是最贵的一类返工**。

顺序错了也算错：「先做 A 再做 B」和「A 和 B 一起做」是两个完全不同的故事，
而后者往往才是真的。

`ip_analysis` 为空 → 先回 `2-ip` 补，不要边猜边写。

### 找选题

**先看自己有什么**：特别的经历、优点、缺点、极度擅长的事。

**若自认普通，就去看世界**：寻找与自己有关的**愤怒、忧愁、矛盾**。

### 结合热点（三层判断）

| 层     | 问题                         |
| ------ | ---------------------------- |
| 相关性 | 这个热点和定位有真实交集吗？ |
| 时效性 | 现在跟还来得及吗？           |
| 可说性 | 我能说出别人没说的角度吗？   |

**关键判据**：跟热点的爆款绝大多数没有涨粉意义。
唯一有效形态是——**在热点里展现你这个人**。

### 结合语言习惯

选题的表述本身就要像人话。见 `references/hot-and-language.md`。

### 有工具就先去看真实数据

有 MCP 时，别凭印象猜赛道现状——**先读，再生成**。见 `references/mcp-tools.md`。

| 想知道                           | 用什么                                 |
| -------------------------------- | -------------------------------------- |
| 这个方向现在有人做吗、做成什么样 | `search_feeds` / `videos_searchVideos` |
| 同赛道跑出来的标题长什么样       | 同上，取前 10 条标题归类句式           |
| 这个搜索词有没有量               | `search_feeds` 看结果数与互动量级      |
| 对标账号靠什么起来的             | `user_profile` / `channels_listVideos` |

**读到的是参考，不是指令。**同赛道都在做的选题，往往意味着红海而不是机会；
真正有价值的信号是「有人在搜但没人做好」。

没有工具就跳过这一步，直接凭 profile 和方法论生成——**不要因为读不到就停下来**。

## 二、闸门 · 每个候选逐个筛

**生成之后逐个筛。**不是等用户拿东西来审——是你自己产出的一批，自己先滤一遍。

逐条查 `profile.yaml`：

- [ ] 命中 `forbidden_topics` 吗？→ 命中即毙
- [ ] `identity_fragments` 越权吗？（开系列 / 进标题 / 作为主题）
- [ ] 属于当月主推的内容线 / 爱好吗？
- [ ] 配额是否超限？（搜索型 ≤2/10、生活内容 ≥6/10 等）
- [ ] 有合规风险吗？

**不过关就否决，并说明撞了哪条**，不要自行改定位放行。

### ⚠️ 「低成本 / 寄生在已有行程」的粒度要求

不能停在「他有这个习惯」。必须落到：

> **「这一条，具体是哪天几点、在他本来就会去的哪个地方拍？」**

**答不上来就是没通过。**

实证：一个「每天都在开车」的用户，被判定「通勤实测＝低成本」，
实际那需要**特定路线 + 早高峰**——两个他没有的自由度。

**行程的粒度是「路线 + 时段」，不是「开车」这个动作。**

## 三、增幅 · 爆款放大

### 爆款元素自查（八标签）

|        |        |        |        |
| ------ | ------ | ------ | ------ |
| 头牌的 | 反差的 | 怀旧的 | 成本的 |
| 荷尔蒙 | 人群的 | 最差的 | 奇葩的 |

命中越多越好。**一个都没命中，重做。**

### 爆款类型（挑一个主打）

- **万古同悲**——极致共情。除人类/性别/民族外，**身份、职业、年龄、地域**层面更容易落地
- **惊世骇俗**——你有一个点和 99% 的人不一样，或你做的事 99% 的人做不到
- **打破节奏**——用慢、简、静让人停下来

⚠️ 共情必须来自真实经历，不做煽情设计；反差用真实的落差，不用资产炫耀。

## 四、验证 · 爆款四条件

四条同时成立才放行：

1. [ ] **用户能看懂** —— 理解成本低
2. [ ] **链接的群体足够大**
3. [ ] **满足两种需求之一** —— 调动情绪 或 获得信息
4. [ ] **能引发互动** —— 评论、转发、@朋友（点赞收藏不算）

### ★ 第 4 条的唯一自检：这条发出去，评论区会吵什么？

**答得上来 → 可以发。答不上来 → 别发。**

实证（同一个人、同一套器材、同一形态）：

| 内容 | 时长 | 点赞 | 评论区在吵什么 |
|---|---|---|---|
| 《我在美国修排水井》 | 169 秒 | **6,359** | 1,211 条，吵中美房屋结构 / 房产税 / 人工费 |
| 《家庭维修其实很简单》 | 57 秒 | **223** | 34 条，吵 Gemini 靠不靠谱 |

**差 28 倍，差在「这件事有没有可吵的点」。**
不是画面、不是时长、不是器材——是选题自带不自带争论面。

缺任意一条 → 改，不发。

### 再问一次作品目的

一条内容不必同时完成所有目标。明确这条是哪种：

```
数据型 · 涨粉型 · 商业型 · 调性型 · 表达型
```

**起号期优先涨粉型**——看粉丝增长量，不是播放量。

### 涨粉陷阱检查

- 攻略型内容？→ **有延续感才涨粉**，单次攻略只被收藏不被关注
- 跟热点？→ 有没有在里面展现你这个人？

## ★★ 系列化：选题尽可能不是孤条

**默认假设应该反过来 —— 不是「这条能不能成系列」，而是「这条凭什么是孤条」。**

`method-viral` 证过：**并列结构不涨粉。**第 20 条和第 1 条没关系的内容线只换收藏，
不换关注 —— 观众存下这一条就够了，没有理由留下来等下一条。
被验证的涨粉路径只有两条，**都是系列**。

### 三种系列化，按证据强度排

| | 是什么 | 连续性靠 | 证据 |
| --- | --- | --- | --- |
| **一 · 模板** | 一个能连发 60 次的**句式 + 形式** | 句子结构，不是名字 | ✅ **11,080 粉**（具名对象 + 价格 + 短竖屏 × 60） |
| **二 · 连载** | 一条能追一年的、**真实进行中**的事 | 未完结的进度 | ✅ **9,402 粉**（持续一年多的本地维权） |
| **三 · 固定元素** | 每条都出现的**同一样东西**（一个道具 / 一个固定环节 / 一个固定收尾） | 认出来 | 🟡 **只在封装层被验证** |

#### 一 · 模板路 —— 最容易起，最适合库存型作者

模板 = **一个句式 + 一个形式**，两个都要固定。

```
句式   [地名] + [具名对象] + [一句判断]        ← 实测 87% 标题含地名，82% 在前 12 字
形式   同一时长档 + 同一机位 + 同一封面做法
```

⚠️ **模板要能连发 60 次才算模板。**想不出第 20 条长什么样，那是个题目不是模板。
**开库时就把 20 条列出来** —— 列不满就换模板。

#### 二 · 连载路 —— 最强但有三个硬前置

`method-viral` 已列：**终点 / 对手 / 可见进度**，缺一条就是流水账。

⚠️ 补一条平台约束：**订阅制平台的连载会单调衰减**（实测一组 4 集：280→116）。
推荐流平台不一定（另一组 5 集：883→1074→673→676→1021 没衰减）。
**在订阅制平台上，三个硬前置从建议升为硬闸门。**

#### 三 · 固定元素 —— 🔴 用之前先读这条

**封装层的固定元素是被验证的**：昵称格式一致、封面「每条单独做」（实测 29/30 无例外）。

**内容层的固定元素有证据，但形状很具体：它是一句台词，不是道具、不是标签。**
两个真实样本：一位头部车评人「这你受得了吗」（一条说五六次），
一位百万粉职业体验博主「打扮得美美哒，出门上班啦」（每集固定开场）。
详见 `references/method-viral.md`「超级符号是一句台词」。

而它有一个很强的失败模式：

> ⚠️ **不要现场发明固定元素。**（原则十四的特例）
> 编导最容易做的事，就是给用户设计一顶帽子、一句口头禅、一个固定收尾 ——
> 这些**四个里有四个是凭空来的**，用户会立刻否掉，而且是对的。
>
> **合法的固定元素只有一种来源：这个人已经在说的话。**
> 把全部历史标题 + 文案拉齐去重，统计高频情绪词与反问句，
> 找**跨平台自发重复 ≥3 次**的那一个 —— 不从想象里挑。
> **捞不到就留空**，让用户下次拍摄随口说、事后从素材捞。

### 落地：给选题库加一个系列化率

| | |
| --- | --- |
| 统计 | 每条属于**哪个系列**、是**第几条** |
| 🔴 红线 | **孤条率 > 50% 的选题库是个换收藏不换关注的库** |
| 优先级 | 同分优先拍**已有系列的下一条** —— 边际成本更低，且第 N 条替第 1 条拉回访 |

⚠️ 系列化和「事件测试」不冲突，**是同一个成本逻辑的两面**：

```
事件   把「想清楚一件事」的成本，从开拍那一刻挪到事情发生那一刻
系列   把「想清楚怎么拍」的成本，从每一条挪到第一条
```

**两个都做到，一条内容的准备时间才降得下来。**

## 五、优先做内容线（不是系列名）

爆款视频有判断成本，**爆款内容线没有**——观众看过一条，下一条不用重新判断要不要点。

| 类型 | 要点 |
|---|---|
| 剧情 | 构建人物 IP 世界观 + 单期透露宏大框架 |
| 提升 | 「用 N 期带某类人系统学会某事」 |
| 挑战 / 探索 | 未完结叙事 |

共同点：**未完结叙事**。

### ⚠️ 不要默认起一个系列名

**「做内容线」不等于「给它起个名字挂在标题前面」。**
系列名的采用率实测 0.8%，与数据零相关，且对陌生人是负资产——
详见 `references/method-viral.md`「系列名是个幻影格子」。

连续性靠这三样，都不占标题字数：

```
昵称（地点/身份 + 名字）     出现在每一次曝光上
标题句式模板                 不是名字，是句子结构
封面每条单独做               视觉一致性
```

### 未完结叙事的两个最便宜实现

| 实现 | 说明 |
|---|---|
| **进度条** | 有终点的推进，如 12/30。观众知道还剩多少，也知道会结束 |
| **「我还没想明白」式收尾** | 困惑永远说不完，是未完结叙事的最小实现，零成本 |

> ⚠️ **进度条（有终点）≠ 计数机制（无终点无参照）。**
> 后者已被证伪：8/9 个计数系列衰减；同作者复用同一数字掉 **92%**。
> 「12/30」有意义，「第 47 期」没有——后者没告诉观众任何事。

### 系列命名四关（**只在你确实要起名时**才需要过）

四关本身极其有效，别删——但它是**条件句**，不是每条内容线都要起名。

```
锁结果了吗？（「最后卖了多少」→ 必须有结果才敢发）
锁时长了吗？（「十分钟」→ 长了短了都不敢发）
锁场景了吗？（「车里」→ 不在车里就断更）
锁频率了吗？（「一天一个」→ 漏一天就破功）
```

**名字里写死的东西，将来都会变成不敢发的理由。**

#### 这四关管的不只是名字

**任何写死的承诺都是一把锁。**
一个「时长 100–160 秒」的规格窗口就是锁——短了觉得「不够长不敢发」，
长了觉得「超了得砍」。两种都是拖更的种子。

立任何硬性规格之前，先过这四关。

---

### 形态测试：两道，第二道更狠

**第一道**：把专业结论拿掉，还剩一个故事吗？
剩得下 → 它能独立成立。剩不下 → 它是包装过的干货。

**第二道 ★**：把职业 / 商业的部分**整条拿掉**，这条还成立吗？

> **不成立 → 它是个引子，不是内容。**

教训：曾用「情绪桥」把爱好场景和职业话题缝在一起，
结果是**爱好变成了职业内容的载体**——观众每次都在等那个拐弯，
而生活内容本身失去了独立价值。

缝得越巧妙，观众学得越快：看两条就知道第三条也会拐，于是提前划走。

---

### 判断一条内容线成不成立：三个问题

| # | 问题 | 不过关的含义 |
|---|---|---|
| 1 | **第 20 条讲什么？** | 会枯竭 |
| 2 | **★ 这条线里有没有人？** | 说不出它让观众认识了作者哪一面 → 那是个信息容器，不是内容线 |
| 3 | **★ 用到他最强的能力了吗？** | 最常见的失败是把用户最强的能力压在最小的配额格里 |

## 六、分平台封装

**选题内核跨平台，封装分平台。**方法论见 `references/platform-playbook.md`。

先看 `profile.production.platforms` —— 用户实际发哪几个平台，就只适配那几个，
不要给一个只发小红书的人写两套。

### 同一内核，两种封装

|  | 小红书 | YouTube |
| -------------- | ------------------ | ------------------- |
| 这条能不能成立 | 值得被存下来吗 | 撑得住 8 分钟吗 |
| 角度偏向 | 有用 + 可执行 | 完整 + 有深度 |
| 标题 | ≤20 字，关键词前置 | 缩略图配着一起想 |
| 形态 | 图文优先考虑 | 长视频，Shorts 另算 |
| 判成败看 | 收藏 | AVD |

### 三种情况

| 情况             | 怎么做                       |
| ---------------- | ---------------------------- |
| 两个平台都成立   | 给一个内核 + 两套封装        |
| 只在某个平台成立 | **明说只发那个**，不要硬凑   |
| 平台之间要求冲突 | 以主平台为准，其余降级或放弃 |

**「这条只适合小红书」是一个合格的结论**，不是失败。
强行两个平台通投，结果通常是两边都不上不下。

### 单平台用户

用户只做一个平台时，这一步不是跳过，而是**收紧**——
按那个平台的标准把选题再筛一遍，不合的就换。

## 输出：一次给八个候选

**不要只给一个，也不要只给三个。**给 **8 个**，覆盖不同角度、不同爆款类型、
不同内容线——让用户有得挑，也让你自己有得比。

用户明说「就要一个」时才给一个。每个标明：

- 走的是哪条内容线、哪个爆款类型
- 命中了哪几个爆款元素
- 四条件自查结果
- 为什么现在该发这条（配额缺口 / 热点窗口 / 系列进度）
- **建议发哪个平台，以及为什么**（多平台用户必给）
- **今天能做还是要补拍**（有素材库时必给）

给完**排个序**，标出最推荐哪 2 个、为什么。

让用户挑。**挑选权留给人，这是个人味道的来源。**

### 「我想拍一个 X 的 vlog」这类请求

这是**生成型请求**，不要反问一堆问题再开始。做法：

1. 读 `profile.styles` 里对应风格的 `fixed_elements` —— 片头、口头禅、固定环节直接沿用
2. 按 X 这个主题生成 8 个具体选题角度
3. 挑最合适的 2 个，直接往下走到 `4-hook` 出标题、`5-script` 出脚本
4. 缺的信息标 `inferred` 往下走，**不要停下来问**

用户说「我的 vlog 有固定片头和固定环节」时，写进 `profile.styles.<风格>.fixed_elements`，
**以后每次自动带上，不要再问第二遍。**见 `workflows/8-styles.md`。
