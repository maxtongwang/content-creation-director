# 3 · 选题决策

**输入**：`profile.yaml`（没有就先回 1-account）
**产出**：`topic-card.yaml`
**方法论**：`references/method-viral.md`、`references/method-account.md`、`references/hot-and-language.md`

---

## 先生成，再筛

**用户来要选题，不是来给选题打分的。**
就算他只带来一个想法问「这条行不行」——先生成一批，再把他那条放进去一起比。

```
选题生成  →  定位闸门  →  爆款增幅  →  验证  →  排序交付
（大量做）    （滤掉不能做的） （放大）    （筛）    （给 8 个）
```

**闸门是筛选器，不是入口。**先有东西才谈得上筛。
但闸门本身不放水——滤掉就是滤掉，不为了凑数放行。

**定位是闸门，爆款是放大。**爆款元素只能在定位允许的范围内放大，没有改写定位的权力。

### 开工前先读 learned

`profile.learned` 是历次复盘验证过的结论，**这是 skill 变准的地方**：

| 读什么 | 怎么用 |
|---|---|
| `works` | 验证有效的方向和句式，优先多出几个 |
| `fails` | 证伪过的，**不要再提** |
| `audience.常问` | 观众反复问的问题，**天然选题库**，直接拿来用 |
| `open_questions` | 待验证假设，可以设计一条内容去验它 |

没有 `learned`（第一次用）就跳过，正常生成。

## 零、选题的四个来源

**「给我几个选题」不该只靠模型想。**四个来源，能取几个取几个：

| 来源 | 拿什么 | 怎么取 |
|---|---|---|
| **你是谁** | 定位、支柱、禁区、验证过的 `learned.works` | `profile.yaml` |
| **观众要什么** | 评论区反复问的问题 | `learned.audience.常问`；有 MCP 就 `get_feed_detail` 读评论 |
| **平台现在在推什么** | 同赛道当下的排名与量级 | `search_feeds` / `videos_searchVideos` |
| **你拍得出什么** ★ | 素材库里已有的画面 | `search_clips` / `find_broll` |

### 第四个来源最容易被忽略，但最实用

**素材库决定哪些选题今天就能做，哪些要等拍摄。**
每个候选都标一句：

```
[今天能做]  素材库里有对应画面，直接进 5-script → 6b-autoedit
[需补拍]    要拍什么、几个镜头，进 shoot_needed
```

一个「今天能做」的普通选题，价值经常高过一个「要拍三天」的好选题。

### 关于「最近热门」——先说清楚能做到什么

**没有热榜接口。**能拿到的是「现在搜这个词，排在前面的是什么」，这是代理指标，不是热榜。

| 平台 | 能拿到 | 可信度 |
|---|---|---|
| YouTube | `videos_searchVideos` 支持 `publishedAfter` + `order`，**能查「近 14 天内发布、按播放排序」** | 高，是真实的近期表现 |
| 小红书 | `search_feeds` 看某关键词当下的排名与互动量级 | 中，是排名不是热度 |
| 小红书 `list_feeds` | 首页推荐流 | **低——这是推给你的，不是全网热的** |

**`list_feeds` 的偏差要主动说明**：它是按你的账号画像推的，
拿它当「大家都在看什么」会把你自己的兴趣误当成趋势。

**没有工具时不要停**——凭 profile 和方法论照常生成，只是少了现状校准。

### 第四来源查完要给结论

检索**命中为 0** 时，含义不是「这个来源没用上」，而是
**「本轮全部选题都是需补拍」**。

此时**必须先排补拍，再排选题**——否则会出现「选题一大把，一条也发不出去」。

### 选题库是存量，四来源是流量

| | 性质 | 正确用法 |
|---|---|---|
| 选题库 | **存量**，用完就没 | 本周流量不够强时**调一条救场** |
| 四个来源 | **流量**，每周自己长 | 主力 |

拿存量当主力，两个月后就空了，而且空的时候毫无预警。

## ★ 选题卡最小字段集（每条都要有，缺一项就是没跑完）

**这一节是 `method-account` 与 `method-viral` 的必做项的合并清单。**
以前它们散在两份文档里，结果是「知道有这回事，但每次都漏几项」。

```
□ 选题                该拍什么
□ ★★ 对象            这条里那个具体、外部、可辨认的东西 —— 填不上就不拍
□ ★★ 挑人度          通 / 半 / 独 —— 换个人还能不能拍
□ 内容线 / 形态        属于哪条线，怎么拍
□ ★ 爆款元素          八标签命中哪几个 —— 一个都没命中 → 重做
□ ★ 爆款类型          万古同悲 / 惊世骇俗 / 打破节奏，挑一个主打
□ ★ 四条件            ①看得懂 ②群体够大 ③情绪或信息 ④能引发互动
□ ★ 作品目的          数据型 / 涨粉型 / 商业型 / 调性型 / 表达型
□ ★ 脚本结构          讲故事 / 晒过程 / 教知识 / 聊观点 / 尬段子 / 说产品
□ ★ 呈现形式          口述 / 视频+配音 / 图片+配音 / 情景剧
□ 闸门结果            命中哪条禁区，或为什么放行
□ 四来源标注          ✅🟡❌ 逐一
□ 今天能做 / 需补拍    素材库查过没有
□ 平台                多平台用户必给
```

### 带 ★ 的六项最容易被漏

它们全部来自那两份方法论，而**不在多数人记得住的清单里**。
其中三项的判据是硬的：

| 字段 | 硬判据 |
|---|---|
| **对象** | **填不上 → 不拍**（见下一节） |
| 爆款元素 | **一个都没命中 → 重做**，不是「可以再想想」 |
| 四条件 ② | 群体够大 —— **这是唯一真闸门**。太窄的降级为弹药，招错人的只当背书 |
| 作品目的 | **起号期优先涨粉型**。全是数据型 → 只涨收藏不涨关注 |

## ★★ 两个可以自己算的闸门

**编导有两件事要做：了解这个人，和给这个人客观工具。**
下面两项是**用户自己就能算的**，不需要相信编导的判断。

### 一 · 对象测试 —— 这条里那个具体、外部、可辨认的东西是什么

```
一个数字 · 一个地方 · 一群人 · 一件物 · 一个变化
```

**答不上来 → 不拍。**没有对象的内容只有「我今天去了哪儿、我怎么想」，那是流水账。

一个真实小账号（111 条，已剔离群值）的头尾对照：

| | 有对象 | |
| --- | --- | --- |
| 头部 7 条 | **7 / 7** | 一个吓人的数字 · 我家 · 一群人 + 一个变化 · 一个职业转折 · 一个具体社区 |
| 底部（≥5 分）7 条 | **0 / 7** | 只有「我去了哪儿 / 我怎么想」 |

头部那 7 条**长度从 18 秒到 8 分都有，vlog 与非 vlog 都有** ——
**形式不是变量，有没有对象才是。**

> 它和 `method-account` 的转化触发条件是同一条：
> **具体、可辨认的对象（地点 / 物件 / 型号）**。
> 那一节讲的是它决定转化；这里补一句：**它同时决定分发。**

### 二 · 挑人度 —— 换个人还能不能拍

`method-viral` 第七节分了 **IP 型**与**内容型**两种博主，但没给可操作的判据。补上：

| 记号 | 含义 | 性质 |
| --- | --- | --- |
| **通** | 换个处境相同的人也能拍 | 拿得到分发 |
| **半** | 需要一段普通人都有的经历（后悔过、选过、错过） | 中间态 |
| **独** | 需要这个人独有的履历事实 | **互动质量高，但拿不到分发** |

实测（同一账号）：个人故事簇**中位评率是全站的 4.1 倍**，但中位曝光是全站最低那几档。

```
挑人的内容    互动质量高，分发差
不挑人的内容  分发好
```

**处方不是二选一，是：用不挑人的选题 + 这个人自己的表达。**
人设从**怎么讲**里渗出来，不用把履历塞进选题 —— 这正是「人格是副产品」。

⚠️ **独** 那一档不要清零：它是互动质量的来源。但**不能当主力配额**，
否则内容会变成「必须先认识这个人才看得懂」。

### 按线定，不逐条标

同一条内容线里，**作品目的 / 爆款类型 / 脚本结构 / 呈现形式基本是一样的**。
在内容线上定一次，线里的每条继承 —— 逐条标几十次是重复劳动，而且会标得不一致。

**例外**：走机动位的一次性弹药**必须单独标**，它们不属于任何线。


## ★★ 三维打分：选题排序（不是选题生成）

**闸门决定「能不能发」，打分决定「先发哪条」。**两件事，不要混。

### 🔴 只按流量打分，会把账号带偏

真实失效记录：我给一个服务型账号的全部选题打了**流量分**（群体 + 爆款类型 + 对象 + 标题）。
然后按分数反推，又生成了一整组高分选题 —— 结果那一组长这样：

```
我最狼狈的一次 · 我最后悔的三件事 · 我学不动了 · 我最没底气的那一年 · 我这行最不体面的一天
```

**流量分全组第二高。**但对一个卖服务的人来说，
**这不是人设，是简历上的减分项** —— 而流量分完全看不见这一点。

### 三个维度

```
综合分 = 流量 × 0.4  +  变现 × 0.3  +  人设 × 0.3       三项各 0–10
```

| 维度 | 问什么 | 主要成分 |
|---|---|---|
| **流量** | 这条能跑多大（**天花板**） | 群体大小（唯一真闸门）+ 爆款类型 + **有没有对象** + 标题因子 − 执行性扣分 |
| **变现** | 对**变现人设**有没有帮助 | **有没有闸门（权重最大）** + 离生意多近 + 是否筛出可能成为客户的人 − 招同行 |
| **人设** | 这条累积起来把他塑造成谁；**积不积极** | 离「他真实在过的好日子」多近 − 负面/自贬词 + 正向词 |

**第三维的本质**：`W009 人格是副产品` 的打分化 ——
**内容不是描述人设，是塑造人设。**一条一条累积起来的那个人，才是观众看到的人。

### 三条实践规则

| # | |
|---|---|
| **1** | **三个维度的冠军通常互不重叠。**实测：流量冠军是「大群体 + 地名」组，变现冠军是「晒过程 + 闸门」组，人设冠军是「他真实在过的日子」组 —— **单一维度的最优解不是全局最优** |
| **2** | **人设分 ≤2 的内容，每 10 条最多 1 条**，且那一条**必须有收束**（「后来我改了什么」），不能停在惨上 |
| **3** | **变现维度里闸门权重最高。**没有闸门的内容，变现分天然低 —— 这与「转化 = 闸门」一致，不是 bug |

⚠️ **不要用综合分决定「删不删」，只用它决定「同一格里先发哪条」。**
低分往往是**服务另一层漏斗**的内容（见 `method-account` 运营漏斗）。

### 怎么落地

**分数必须能重算，否则它只是编导的偏好。**
每个系数都要指向一条可查的实测；组级人工项要单独列出并说明理由。
**做成脚本，改了选题就重跑 —— 不要手改分数。**

## 一、生成 · 选题两步法

### ⚠️ 涉及本人经历的选题，先核对事实

任何以「我曾经…」「我从…转到…」为前提的选题，
必须先查 `profile.ip_analysis`（职业路径 / 最骄傲的事 / 最挫折的事 / 缺点）。

**不可从公开数据推断本人经历。**推断出的前提会让整条选题作废，
而且用户要花时间纠正——**这是最贵的一类返工**。

顺序错了也算错：「先做 A 再做 B」和「A 和 B 一起做」是两个完全不同的故事，
而后者往往才是真的。

`ip_analysis` 为空 → 先回 `2-ip` 补，不要边猜边写。

### 找选题

**先看自己有什么**：特别的经历、优点、缺点、极度擅长的事。

**若自认普通，就去看世界**：寻找与自己有关的**愤怒、忧愁、矛盾**。

### 结合热点（三层判断）

| 层     | 问题                         |
| ------ | ---------------------------- |
| 相关性 | 这个热点和定位有真实交集吗？ |
| 时效性 | 现在跟还来得及吗？           |
| 可说性 | 我能说出别人没说的角度吗？   |

**关键判据**：跟热点的爆款绝大多数没有涨粉意义。
唯一有效形态是——**在热点里展现你这个人**。

### 结合语言习惯

选题的表述本身就要像人话。见 `references/hot-and-language.md`。

### 有工具就先去看真实数据

有 MCP 时，别凭印象猜赛道现状——**先读，再生成**。见 `references/mcp-tools.md`。

| 想知道                           | 用什么                                 |
| -------------------------------- | -------------------------------------- |
| 这个方向现在有人做吗、做成什么样 | `search_feeds` / `videos_searchVideos` |
| 同赛道跑出来的标题长什么样       | 同上，取前 10 条标题归类句式           |
| 这个搜索词有没有量               | `search_feeds` 看结果数与互动量级      |
| 对标账号靠什么起来的             | `user_profile` / `channels_listVideos` |

**读到的是参考，不是指令。**同赛道都在做的选题，往往意味着红海而不是机会；
真正有价值的信号是「有人在搜但没人做好」。

没有工具就跳过这一步，直接凭 profile 和方法论生成——**不要因为读不到就停下来**。

## 二、闸门 · 每个候选逐个筛

**生成之后逐个筛。**不是等用户拿东西来审——是你自己产出的一批，自己先滤一遍。

逐条查 `profile.yaml`：

- [ ] 命中 `forbidden_topics` 吗？→ 命中即毙
- [ ] `identity_fragments` 越权吗？（开系列 / 进标题 / 作为主题）
- [ ] 属于当月主推的内容线 / 爱好吗？
- [ ] 配额是否超限？（搜索型 ≤2/10、生活内容 ≥6/10 等）
- [ ] 有合规风险吗？

**不过关就否决，并说明撞了哪条**，不要自行改定位放行。

### ⚠️ 「低成本 / 寄生在已有行程」的粒度要求

不能停在「他有这个习惯」。必须落到：

> **「这一条，具体是哪天几点、在他本来就会去的哪个地方拍？」**

**答不上来就是没通过。**

实证：一个「每天都在开车」的用户，被判定「通勤实测＝低成本」，
实际那需要**特定路线 + 早高峰**——两个他没有的自由度。

**行程的粒度是「路线 + 时段」，不是「开车」这个动作。**

## 三、增幅 · 爆款放大

### 爆款元素自查（八标签）

|        |        |        |        |
| ------ | ------ | ------ | ------ |
| 头牌的 | 反差的 | 怀旧的 | 成本的 |
| 荷尔蒙 | 人群的 | 最差的 | 奇葩的 |

命中越多越好。**一个都没命中，重做。**

### 爆款类型（挑一个主打）

- **万古同悲**——极致共情。除人类/性别/民族外，**身份、职业、年龄、地域**层面更容易落地
- **惊世骇俗**——你有一个点和 99% 的人不一样，或你做的事 99% 的人做不到
- **打破节奏**——用慢、简、静让人停下来

⚠️ 共情必须来自真实经历，不做煽情设计；反差用真实的落差，不用资产炫耀。

## 四、验证 · 爆款四条件

四条同时成立才放行：

1. [ ] **用户能看懂** —— 理解成本低
2. [ ] **链接的群体足够大**
3. [ ] **满足两种需求之一** —— 调动情绪 或 获得信息
4. [ ] **能引发互动** —— 评论、转发、@朋友（点赞收藏不算）

### ★ 第 4 条的唯一自检：这条发出去，评论区会吵什么？

**答得上来 → 可以发。答不上来 → 别发。**

实证（同一个人、同一套器材、同一形态）：

| 内容 | 时长 | 点赞 | 评论区在吵什么 |
|---|---|---|---|
| 《我在美国修排水井》 | 169 秒 | **6,359** | 1,211 条，吵中美房屋结构 / 房产税 / 人工费 |
| 《家庭维修其实很简单》 | 57 秒 | **223** | 34 条，吵 Gemini 靠不靠谱 |

**差 28 倍，差在「这件事有没有可吵的点」。**
不是画面、不是时长、不是器材——是选题自带不自带争论面。

缺任意一条 → 改，不发。

### 再问一次作品目的

一条内容不必同时完成所有目标。明确这条是哪种：

```
数据型 · 涨粉型 · 商业型 · 调性型 · 表达型
```

**起号期优先涨粉型**——看粉丝增长量，不是播放量。

### 涨粉陷阱检查

- 攻略型内容？→ **有延续感才涨粉**，单次攻略只被收藏不被关注
- 跟热点？→ 有没有在里面展现你这个人？

## 五、优先做内容线（不是系列名）

爆款视频有判断成本，**爆款内容线没有**——观众看过一条，下一条不用重新判断要不要点。

| 类型 | 要点 |
|---|---|
| 剧情 | 构建人物 IP 世界观 + 单期透露宏大框架 |
| 提升 | 「用 N 期带某类人系统学会某事」 |
| 挑战 / 探索 | 未完结叙事 |

共同点：**未完结叙事**。

### ⚠️ 不要默认起一个系列名

**「做内容线」不等于「给它起个名字挂在标题前面」。**
系列名的采用率实测 0.8%，与数据零相关，且对陌生人是负资产——
详见 `references/method-viral.md`「系列名是个幻影格子」。

连续性靠这三样，都不占标题字数：

```
昵称（地点/身份 + 名字）     出现在每一次曝光上
标题句式模板                 不是名字，是句子结构
封面每条单独做               视觉一致性
```

### 未完结叙事的两个最便宜实现

| 实现 | 说明 |
|---|---|
| **进度条** | 有终点的推进，如 12/30。观众知道还剩多少，也知道会结束 |
| **「我还没想明白」式收尾** | 困惑永远说不完，是未完结叙事的最小实现，零成本 |

> ⚠️ **进度条（有终点）≠ 计数机制（无终点无参照）。**
> 后者已被证伪：8/9 个计数系列衰减；同作者复用同一数字掉 **92%**。
> 「12/30」有意义，「第 47 期」没有——后者没告诉观众任何事。

### 系列命名四关（**只在你确实要起名时**才需要过）

四关本身极其有效，别删——但它是**条件句**，不是每条内容线都要起名。

```
锁结果了吗？（「最后卖了多少」→ 必须有结果才敢发）
锁时长了吗？（「十分钟」→ 长了短了都不敢发）
锁场景了吗？（「车里」→ 不在车里就断更）
锁频率了吗？（「一天一个」→ 漏一天就破功）
```

**名字里写死的东西，将来都会变成不敢发的理由。**

#### 这四关管的不只是名字

**任何写死的承诺都是一把锁。**
一个「时长 100–160 秒」的规格窗口就是锁——短了觉得「不够长不敢发」，
长了觉得「超了得砍」。两种都是拖更的种子。

立任何硬性规格之前，先过这四关。

---

### 形态测试：两道，第二道更狠

**第一道**：把专业结论拿掉，还剩一个故事吗？
剩得下 → 它能独立成立。剩不下 → 它是包装过的干货。

**第二道 ★**：把职业 / 商业的部分**整条拿掉**，这条还成立吗？

> **不成立 → 它是个引子，不是内容。**

教训：曾用「情绪桥」把爱好场景和职业话题缝在一起，
结果是**爱好变成了职业内容的载体**——观众每次都在等那个拐弯，
而生活内容本身失去了独立价值。

缝得越巧妙，观众学得越快：看两条就知道第三条也会拐，于是提前划走。

---

### 判断一条内容线成不成立：三个问题

| # | 问题 | 不过关的含义 |
|---|---|---|
| 1 | **第 20 条讲什么？** | 会枯竭 |
| 2 | **★ 这条线里有没有人？** | 说不出它让观众认识了作者哪一面 → 那是个信息容器，不是内容线 |
| 3 | **★ 用到他最强的能力了吗？** | 最常见的失败是把用户最强的能力压在最小的配额格里 |

## 六、分平台封装

**选题内核跨平台，封装分平台。**方法论见 `references/platform-playbook.md`。

先看 `profile.production.platforms` —— 用户实际发哪几个平台，就只适配那几个，
不要给一个只发小红书的人写两套。

### 同一内核，两种封装

|  | 小红书 | YouTube |
| -------------- | ------------------ | ------------------- |
| 这条能不能成立 | 值得被存下来吗 | 撑得住 8 分钟吗 |
| 角度偏向 | 有用 + 可执行 | 完整 + 有深度 |
| 标题 | ≤20 字，关键词前置 | 缩略图配着一起想 |
| 形态 | 图文优先考虑 | 长视频，Shorts 另算 |
| 判成败看 | 收藏 | AVD |

### 三种情况

| 情况             | 怎么做                       |
| ---------------- | ---------------------------- |
| 两个平台都成立   | 给一个内核 + 两套封装        |
| 只在某个平台成立 | **明说只发那个**，不要硬凑   |
| 平台之间要求冲突 | 以主平台为准，其余降级或放弃 |

**「这条只适合小红书」是一个合格的结论**，不是失败。
强行两个平台通投，结果通常是两边都不上不下。

### 单平台用户

用户只做一个平台时，这一步不是跳过，而是**收紧**——
按那个平台的标准把选题再筛一遍，不合的就换。

## 输出：一次给八个候选

**不要只给一个，也不要只给三个。**给 **8 个**，覆盖不同角度、不同爆款类型、
不同内容线——让用户有得挑，也让你自己有得比。

用户明说「就要一个」时才给一个。每个标明：

- 走的是哪条内容线、哪个爆款类型
- 命中了哪几个爆款元素
- 四条件自查结果
- 为什么现在该发这条（配额缺口 / 热点窗口 / 系列进度）
- **建议发哪个平台，以及为什么**（多平台用户必给）
- **今天能做还是要补拍**（有素材库时必给）

给完**排个序**，标出最推荐哪 2 个、为什么。

让用户挑。**挑选权留给人，这是个人味道的来源。**

### 「我想拍一个 X 的 vlog」这类请求

这是**生成型请求**，不要反问一堆问题再开始。做法：

1. 读 `profile.styles` 里对应风格的 `fixed_elements` —— 片头、口头禅、固定环节直接沿用
2. 按 X 这个主题生成 8 个具体选题角度
3. 挑最合适的 2 个，直接往下走到 `4-hook` 出标题、`5-script` 出脚本
4. 缺的信息标 `inferred` 往下走，**不要停下来问**

用户说「我的 vlog 有固定片头和固定环节」时，写进 `profile.styles.<风格>.fixed_elements`，
**以后每次自动带上，不要再问第二遍。**见 `workflows/8-styles.md`。
