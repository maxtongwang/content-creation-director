# 7 · 复盘与诊断

**输入**：`ledger`（发布履历 + 数据）
**依赖**：本环节的配额与漏斗诊断依赖 `automation/` 层。
没有 ledger 就只能做单条内容的定性诊断，做不了配比和趋势判断。
**取数**：有 MCP 就直接读（`get_feed_detail` / `videos_getVideo` 拉真实互动数据），
没有就让用户贴。见 `references/mcp-tools.md`。
**产出**：诊断结论 + **回流到某个上游阶段**
**方法论**：`references/method-account.md` 运营体系章

---

## 铁律：先看形状，再开处方

不要一上来问「怎么办」。先问**「我现在长什么样」**。

---

## 一、画漏斗

四层，取近 10–20 条的数据：

```
流量  →  兴趣  →  信任  →  成交
播放     完播/互动   关注/收藏    私信/成交
```

---

## 二、对号入座

| 形态       | 长什么样       | 诊断             | 回流到                          |
| ---------- | -------------- | ---------------- | ------------------------------- |
| **健康型** | 标准倒三角     | 状态良好         | 复制成功内容，或扩大流量        |
| **竹竿型** | 四层等宽且都窄 | **内容不好**     | → `3-topic` `4-hook` `5-script` |
| **雨伞型** | 上宽下极窄     | **没有商业定位** | → `1-account` 重做商业定位      |
| **水桶型** | 四层等宽且都宽 | **商业逻辑好**   | → `4-hook` `5-script` 优化呈现  |

**雨伞型最常见也最危险**——流量很好但转化断层，说明内容和变现之间没有桥。
这不是内容问题，是定位问题，别在选题上打转。

---

## 三、先分平台，再下结论

**同一条内容在 A 平台失败、B 平台成功，是常态，不是矛盾。**
合并两个平台的数据看，会把「适配问题」误判成「内容问题」。

### 各平台看哪个指标

|  | 小红书 | YouTube |
| ------------ | -------------- | ------------- |
| 第一指标 | 收藏 | AVD / 留存率 |
| 第二指标 | 主页访问、私信 | CTR、订阅转化 |
| 基本没意义 | 点赞 | 单看点击数 |
| 播放低但正常 | 搜索型内容 | 长尾期内容 |

**用错标准比没有标准更糟。**用播放量判断小红书搜索型内容、
用 Shorts 数据判断 YouTube 频道健康度——都是常见误判。
完整标准见 `references/platform-playbook.md`。

### 三种形状，三种结论

| 现象           | 结论                       | 回流到                                      |
| -------------- | -------------------------- | ------------------------------------------- |
| 两个平台都差   | 内容问题                   | `3-topic` / `5-script`                      |
| 只有一个平台差 | **适配问题**，不是内容问题 | `4-hook` 改那个平台的封装                   |
| 一个平台明显好 | 可能找到主场               | 考虑集中资源，回 `1-account` 重排平台优先级 |

**只发一个平台的用户跳过本节**，直接进第四节。

---

## 四、单条内容的分层诊断

数据不好时，先定位是哪一环：

| 指标          | 差 → 问题在      | 回流到      |
| ------------- | ---------------- | ----------- |
| 封面点击率    | 封面 / 标题      | `4-hook`    |
| 前 3 秒跳出率 | 开头             | `4-hook`    |
| 完播率        | 内容结构、节奏   | `5-script`  |
| 涨粉 / 播放   | 选题没有涨粉属性 | `3-topic`   |
| 私信 / 咨询   | 转化路径断了     | `1-account` |

**不要立刻删视频。**先看数据，再决定。

---

## 五、推荐型 vs 搜索型：两套标准

|          | 推荐型     | 搜索型                   |
| -------- | ---------- | ------------------------ |
| 生命周期 | 3–7 天     | 数月到数年               |
| 看什么   | 完播、涨粉 | **收藏、主页访问、私信** |
| 播放量低 | 是问题     | **是正常形态**           |

**用推荐型的标准判断搜索型内容，等于用跑步成绩评价游泳。**

搜索型健康度看**长尾系数** = D30 播放 / D7 播放，>1.5 说明长尾成立。

## ★★ 流量不积累 —— 该优化的是下限，不是峰值

用户原话：**「流量不是积累的，是突然来的。平时的内容有一个下限比较高的基准就可以了。」**

### 八个真实频道实测，这条成立

| 频道 | n | 中位 | Top10% 占总量 | 最高/中位 | **相邻自相关** |
| --- | --- | --- | --- | --- | --- |
| A | 604 | 481,606 | 32% | **11×** | 0.00 |
| B | 1,238 | 57,948 | 38% | **23×** | 0.17 |
| C | 125 | 35,786 | 33% | **12×** | 0.38 |
| D | 610 | 1,854 | 62% | 255× | 0.01 |
| E | 951 | 1,717 | 56% | 284× | −0.01 |
| F | 1,580 | 760 | 85% | **1,341×** | 0.05 |
| G | 114 | 538 | 75% | 202× | −0.02 |
| H | 218 | 176 | 45% | 26× | 0.12 |

**相邻自相关中位 0.06，八个号里七个在 ±0.12 内。**
「上一条的真实播放量」——信息量最大的那个预测源——对下一条只解释 **0.4% 的方差**。

### ★ 这顺手洗清了流量分

某账号的流量分回测 **ρ=+0.225（解释 5% 方差）**，一度被当成打分失败。

```
账号自己的近期历史   解释 0.4%
流量分               解释 5.0%     ← 12 倍
```

**不是分数差，是目标本身不可预测。**5% 接近这个问题的天花板。

🔴 **但用法要改**：流量分**不是「这条能跑多少」的预期值**。
它是**「这条的下限有多高」**。别拿它承诺峰值，也别在爆款出现后回头夸它准。

### ★★ 真正的分野：高中位的号，爆款倍数反而小

```
下限型   中位 481,606 / 11×    35,786 / 12×    57,948 / 23×
彩票型   中位 760 / 1,341×      1,717 / 284×    1,854 / 255×
```

**八个号单调分开。做大的号不是彩票中得多，是下限抬得高。**

### 什么抬下限 ≠ 什么造爆款

同一个账号 218 条，按特征切成两列：

| 特征 | **抬下限**（中位比） | **造爆款**（最高比） |
| --- | --- | --- |
| **标题第一人称「我」** | **1.93×** | 0.39× 🔴 明确压峰值 |
| **标题带地名** | **1.63×** | 0.69× |
| **≥5 分钟** | **1.59×** | 0.72× |
| 标题带数字 | 1.25× | 0.72× |
| **事件型**（见闸门三） | **1.29×** | **1.44×** ★ 唯一两个都 >1 |
| <60 秒短视频 | 中位最高 | 🔴 **封顶**，最高值全在长视频 |

```
抬下限   第一人称 · 地名 · ≥5 分钟 · 数字 · 事件
造爆款   事件（唯一重合的）
封顶     短视频 —— 下限最高但出不了爆款，别当主力
```

⚠️ **这几列会互相打架。**「第一人称」抬下限 1.93× 却把峰值压到 0.39× ——
**一个想稳的号和一个想爆的号，处方是相反的。先问用户要哪个。**

### 落地

| | |
| --- | --- |
| 打分口径 | 流量分 = **下限分**，不是预期播放量 |
| 排期 | **稳定输出下限高的**。爆款当彩票 —— **中了不复盘归因** |
| 复盘 | 看**中位数的移动**，不看最高值。单条爆了不改配比 |
| 诊断「最近数据不好」 | 先看中位有没有掉。中位没掉 = 只是没中彩票，**不是账号出问题** |

⚠️ **爆款之后不要归因。**相邻自相关 0.06 意味着：
爆款的成因大部分在内容之外（分发抽样、时机、外部话题）。
**把爆款拆解成「成功公式」再照着做，是在拟合噪声。**

★ 值得注意的是：**能被规则控制的只有下限。**
对象管分发、事件管准备时间、系列管回访、调性管信任 ——
**这些闸门全部是抬下限的，没有一条是搏爆款的。这不是巧合，是唯一可做的事。**

## 六、爆款之后

- **先复制同类内容，把势能放大**，不要急着回应评论或解释方法
- 系列生命周期 **3–6 个月**，之后需优化方向
- 变现时机：先集中涨粉，等热度疲软或达到目标体量再接单

## 七、假设回验

策略里的每条判断都应该能被数据证伪。定期检查：

| 假设             | 怎么验                       |
| ---------------- | ---------------------------- |
| 某爆款元素有效   | 命中 vs 未命中的同类内容对比 |
| 某爱好带来精准粉 | 按爱好聚合的涨粉率           |
| 某内容线带来咨询 | 按内容线聚合的私信数         |
| 搜索型长尾成立   | 长尾系数是否 >1.5            |

**连续 5 次采纳后指标无提升 → 该假设标记为已证伪，从策略里删掉。**

不做这一步，策略会慢慢变成一堆没人敢删的迷信。

### 写回 profile ★ 这是 skill 变准的机制

验回来的结论**必须落到 `profile.learned`**，否则下次又从零猜：

```yaml
learned:
  works:
    - what: 标题用身份反差句式
      evidence: 近 12 条里用了的 5 条，平均点击率高 40%
      confirmed: "2026-08-08"
      applies_to: [xiaohongshu]        # 有效性经常是分平台的
  fails:
    - what: 蹭全民热点
      evidence: 连续 5 条播放高但涨粉为 0
      retired: "2026-08-08"
  audience:
    称呼: [<观众怎么叫他>]
    常问: [<反复出现的提问>]           # 这是天然选题库，直接喂给 3-topic
```

**规则**：

| 项 | 要求 |
|---|---|
| 只写验证过的 | 猜测不进 `learned`，进 `open_questions` |
| 标平台 | 一个平台有效不等于另一个有效 |
| 标日期 | 平台规则会变，旧结论要能被重新质疑 |
| `fails` 不删 | 留着防止以后又提一遍同样的错主意 |

### 区分「这一条差」和「这一类差」

**判断方法：把同一账号的内容按类型分组算中位数，而不是只看最高的几条。**

实证（一个全口播账号，同一张脸、同样时长、同一批受众）：

| 类型 | 点赞 |
|---|---|
| 讲身份 / 情绪 / 打脸共识 | 1,680 · 1,255 · 982 |
| 讲自家产品和干货 | 17 · 12 · 22 · 28 · 36 · 48 |

**差 50 倍。**

只看爆款会以为「他做得挺好」，**分组算中位数才看得出有一整类内容在拖后腿**。
最高值是运气的上界，中位数才是这一类的真实水平。

---

下次进 `3-topic` / `4-hook` 前**先读 `learned`**：
`works` 里的优先用，`fails` 里的不要再提，`audience.常问` 直接当选题源。

## 八、回流是本阶段的真正产出

诊断完必须给出**回到哪个阶段、改什么**，不能停在「内容要更好」。

```
❌ 建议提升内容质量
✅ 漏斗是竹竿型 → 回 3-topic，近 10 条里 7 条一个爆款元素都没命中
```
