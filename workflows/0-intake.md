# 0 · 需求澄清

**何时用**：不确定用户处在哪个阶段，或信息不足以开工。

**铁律：最多问 3 个问题。**问多了用户会失去耐心，而且大部分信息可以边做边补。

---

## 先自己判断，再问

问之前先从用户的话里提取，能推断的不要问：

| 用户说了什么 | 能推断出 |
|---|---|
| 提到具体平台 | 目标平台 |
| 提到某条内容数据 | 已有账号，走 7-review |
| 提到「想做」「准备做」 | 零起步，走 1-account |
| 提到某个具体选题 | 走 3-topic |
| 贴了文案或脚本 | 走 4-hook 或 7-review |

---

## 三个问题的优先级

按这个顺序挑最缺的三个：

1. **有账号了吗？做多久了？** → 决定走定位还是走复盘
2. **靠什么赚钱 / 想靠什么赚钱？** → 商业定位是全流程地基
3. **这次具体想要什么？** → 一份定位？一个选题？一个脚本？

**次级问题**（前三个已知时才问）：
- 平台是哪个？
- 能出镜吗？
- 一周能做几条？

---

## 问法

用具体的二选一，不要开放式提问。

```
❌ 你想做什么样的内容？
✅ 你是想靠这个号接广告，还是给自己的生意引流？
```

```
❌ 你的优势是什么？
✅ 有什么事是你能做、但你身边大部分人做不到的？
```

---

## 出口

信息够了就说明**判断结果**和**下一步去哪**，然后直接开始，不要再确认一遍。

```
明白了，你是[判断]。我们先做[阶段]，产出[文件]。
```
