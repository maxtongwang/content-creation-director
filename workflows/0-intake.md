# 0 · 需求澄清

**何时用**：不确定用户处在哪个阶段，或信息不足以开工。

**铁律：最多问 3 个问题。**问多了用户会失去耐心，而且大部分信息可以边做边补。

---

> ★★★ **了解用户这一环：疯狂追问，榨干为止。**停得太早是最大的失效模式 ——
> 一个真实项目里最要命的四条事实全在第 14 轮之后，而「上次为什么停」到第 16 轮才问出来。
> **追问顺序与停止信号见 [`1b-discover`](1b-discover.md)。**

## 顺序：先榨干已有的，再去读，最后才问

```
用户已经说的  →  能自动读的  →  能合理推断的  →  剩下的才问
（免费）         （MCP）        （标注 inferred）   （最多 3 个）
```

**每往右一步，成本都上升一个量级。**跳过左边直接问，是最贵也最烦人的做法。

---

## 一、先从用户的话里榨

问之前先把用户已经说的全部提取出来，**能推断的不要问**：

| 用户说了什么                     | 能推断出                                 |
| -------------------------------- | ---------------------------------------- |
| 提到具体平台                     | 目标平台，且能定平台标准                 |
| 提到某条内容数据                 | 已有账号，走 `7-review`                  |
| 提到「想做」「准备做」           | 零起步，走 `1-account`                   |
| 提到某个具体选题                 | 走 `3-topic`                             |
| 贴了文案或脚本                   | 走 `4-hook` 或 `7-review`                |
| 说了自己的职业 / 身份            | IP 的「身份」要素，别再问一遍            |
| 抱怨某类内容                     | 潜在的 `forbidden_topics` 线索，回头确认 |
| 提到「没时间」「一周就能拍一条」 | `production.weekly_capacity`             |
| 提到设备、能不能出镜             | `production` 段                          |

**用户随口说的一句话，往往能填 profile 里的三个字段。**接住它们。

---

## 二、再看能不能自动读

用户有账号时，先探测有没有对应平台的 MCP 工具：

| 有工具 | 走 `1d-scan`，读完再问     |
| ------ | -------------------------- |
| 没工具 | 走 `1c-backfill`，让用户贴 |

见 `references/mcp-tools.md`。**探测失败不要停，转人工继续。**

---

## 三、剩下的才问，最多 3 个

按这个顺序挑最缺的三个：

1. **有账号了吗？做多久了？** → 决定走定位还是走复盘
2. **靠什么赚钱 / 想靠什么赚钱？** → 商业定位是全流程地基
3. **这次具体想要什么？** → 一份定位？一个选题？一个脚本？

**次级问题**（前三个已知时才问）：

- 平台是哪个？
- 能出镜吗？
- 一周能做几条？

### 问法

用具体的二选一，不要开放式提问。

```
❌ 你想做什么样的内容？
✅ 你是想靠这个号接广告，还是给自己的生意引流？
```

```
❌ 你的优势是什么？
✅ 有什么事是你能做、但你身边大部分人做不到的？
```

---

## 四、不要为了填表而问

**profile 不需要一次填满。**缺的字段可以标 `<待补>`，在后面的环节里自然补上。

| 什么时候必须问         | 什么时候可以先空着                    |
| ---------------------- | ------------------------------------- |
| 商业定位（后面全靠它） | 超级符号                              |
| 禁区（只能本人说）     | 系列规划                              |
| 当前环节的直接输入     | 风格档案（有多形态时再做 `8-styles`） |

判断标准很简单：**这个字段缺了，当前这一步做不下去吗？**
做得下去就先走，别拦着用户。

---

## 出口

信息够了就说明**判断结果**和**下一步去哪**，然后直接开始，不要再确认一遍。

```
明白了，你是[判断]。我们先做[阶段]，产出[文件]。
```

同时说清**推断了什么**，给用户一个纠正的机会（但不要停下来等）：

```
我先按「你主做小红书、能出镜、一周两条」往下走，不对随时说。
```
