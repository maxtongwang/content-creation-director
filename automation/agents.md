# 自动化 Agent

**⚠️ SYNC**：本文所有 agent 的判断逻辑都来自 `workflows/`。
创作层的环节更新时，对应 agent 的行为也要跟着改。改动前查 [`../docs/sync-notes.md`](../docs/sync-notes.md)。

---

## 分层

```
创作层（人 + Claude 协作，产出创作决策）
    ↓ profile / topic-card / script / edit-plan
automation（agent 执行，处理连续性事务）
    ↓ ledger
回流到 workflows/7-review
```

**原则：创作靠判断，发布靠规则。**判断不能自动化，规则可以。

---

## LEDGER · 前提，必须先做

**当前最大的缺口。**所有配额类规则都需要历史才能判断：

| 规则 | 需要的历史 |
|---|---|
| 搜索型 ≤2/10 | 近 10 条的 content_type |
| 内容线配比 | 近 18 条专业内容的 content_line |
| 低成本内容 ≥1/8 | 近 8 条的 pillar |
| 每月主推 2 个支柱 | 当月已用 pillar |
| 片尾邀请 1/3 | 近 3 条的 has_invite |
| 风格配比 | 近 12 条的 style |

**没有 LEDGER，这些一条都跑不了。**

## A1 · 选题 Agent（每日）

**读**：ledger（配额缺口）、素材库、外部信号、profile
**依据**：`workflows/3-topic.md` 的完整逻辑
**产出**：3 个选题候选（不是 1 个）

```
优先级：
1. 配额缺口（缺什么补什么，不是想到什么发什么）
2. 归档素材的回访到期
3. 生活标签保护触发
4. 常规轮换
```

**必须遵守**：
- 定位闸门在前（`3-topic` 第一步）
- 产出 3 个候选让人挑 —— **挑选权留给人，这是个人味道的来源**
- `forbid: 以「讲过了」为由否决选题`

---

## A2 · 剪辑 Agent（每次拍摄后）

**读**：素材、转写、script.yaml、profile.styles
**依据**：`workflows/6-edit.md` + `8-styles.md`

```
执行顺序：识别风格 → 素材打标 → 口播驱动分段 → 按脚本选镜 → 出片
```

**必须遵守**：
- 先识别风格再动手，识别不出就问，**不猜**
- 按 style.edit 的参数约束所有决策
- 每个镜头必须有 cut_reason，缺就退回脚本阶段

---


### 禁止写进文案的内容

**不得把 profile 中 `_internal_*` 的内容写进口播、标题或字幕。**
那是判断依据，不是台词。

这类句子是总结性的、读起来最「点题」，所以最容易被选中当标题或开场白——
写进去之后，观众听到的是本人在自我评价，效果与本意相反。

可念的只有 `examples` 与 `correct_form` 里的句子。
判断方法见 `workflows/2-ip.md` 第五节。

## A3 · 切片 Agent（长内容发布后）

**铁律：每条切片必须自成一体**（独立 hook + 完整观点 + 结论）。

```
❌ 从中间截一段（缺前因后果，观众看不懂）
✅ 按转写的语义段落切，不按时间等分
```

约束：一条长内容切 ≤5 条；与母版间隔 ≥3 天；标题单独写。

---

## A4 · 记账 Agent（发布后）

```
回写 ledger 两层 → 建立语义索引 → 按 polling 表持续回采
→ 触发回访提醒 → 更新 queue 状态 → 周期对账 → 生成复用候选
```

**原则：发布即记账。**agent 自己是发布者，不靠事后抓取猜测。

---

## A5 · 排期 Agent（持续）

**职责**：决定「下一条发什么、什么时候发」。`autonomy: full`，不需人工确认。

```
分平台计算配额缺口
→ 过滤违反 rhythm 约束的候选
→ 缺口最大者优先出队
→ 队列低于 min_buffer_days 触发 fallback
```

**禁止**：按拍摄顺序发布；为清空队列突击连发；违反 max_consecutive_* 任一约束。

发布前检查：标题长度符合平台上限、登录状态、当日未超上限。

---

## A6 · 审查 Agent

**依据**：`workflows/9-deliver.md`（三条硬标准）+ `3-topic.md`（定位闸门）

```
gate_1 定位合规  硬闸门，有否决权，无改写权
gate_2 增幅建议  建议性，不可推翻 gate_1
gate_3 冲突裁决  定位优先；记录冲突供长期回验
```

### gate_1 检查项（价值观层，命中即否决）

- 命中 `tone.表达标准.forbidden_sentences` → **否决**
- 文案中出现 `tone._internal_*` 字段的内容 → **否决**
- 违反 `surface_rule.hard_rules` → **否决**

这三项没有「改一改就放行」，因为它们不是质量问题，是**这不是本人**。

### gate_2 的禁区

**不得以「数据会更好」为由建议修改价值观层字段**
（`tone` / `production` / `identity_exposure` / `forbidden_topics` / `surface_rule`）。

数据能验证「做什么有效」，验证不了「该怎么做人」。
gate_2 的建议权只覆盖数据层：支柱、内容线、配比、形态。

若某条增幅规律长期被否决、但同类内容表现确实更好 → **提示人工复议定位**。
定位可以被数据挑战，但只能被人改，不能被 agent 改。
**价值观层连挑战都不该由 agent 发起。**

## 建设顺序

| 阶段 | 做什么 | 理由 |
|---|---|---|
| 1 | **LEDGER** | 不做这个，A1 的规则全是空转 |
| 2 | **A1 选题** | 最便宜、见效最快 |
| 3 | **A6 审查** | 紧跟 A1，选题出来就过审 |
| 4 | **A4 记账** | 闭环，让 A1 越跑越准 |
| 5 | **A5 排期** | 依赖 ledger + 平台接口 |
| 6 | **A2 剪辑** | 最难，依赖转写质量与素材打标 |
| 7 | **A3 切片** | 依赖 A2，且长内容多了才有价值 |

---

## 边界

**人在环上，不是人在环中。**

流水线的价值在于**消除重复劳动，不在于消除判断**。
全自动产出的内容会趋同、会平均、会失去棱角。
判断恰恰是这个账号唯一不可复制的资产。
